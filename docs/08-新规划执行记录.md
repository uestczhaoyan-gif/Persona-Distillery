## 执行授权与节奏

用户授权每次推进一个小节点，验证后提交并推送 GitHub；额度允许时继续后续节点，不在每个节点重复征询。沿用 `main` 分支，正常推送，不强推；先核对远端并协调新变更，不覆盖其他工作。

已更新现有 heartbeat `persona-distillery-5`，每 5 小时回到当前聊天检查实际 Codex 五小时、周额度及普通使用权限。有额度就连续推进；额度耗尽时保存检查点，下次调度重新检查。五小时调度不等于账户必然在该时刻重置，周额度仍可能限制执行。禁止购买额度、使用重置券或绕过限制。

每个节点流程：读取检查点和相关模块 → 确定最小交付与验证 → 实现 → 针对性验证/必要回归 → 更新记录 → 提交 → 推送 → 核对远端 SHA → 更新本地检查点 → 下一节点。状态未变不反复通知；实质进展、完成、新失败或需要用户操作时再通知。

检查点使用被 Git 忽略的 `.work/expansion-checkpoint.json`，至少记录计划版本、当前节点、下一动作、最近验证、最近提交与同步状态、额度快照、外部阻塞次数及占用状态。不要复用旧计划的完成标记或停止计数。开始时检查是否有正在执行的工作，避免重入；异常中断后先核对进程和文件变化再接管。

本地任务需要机器开机、桌面应用运行、项目目录可访问。自动任务使用默认权限，网络或回环被限制时按工具的授权机制执行；不能将权限失败写成测试通过。
