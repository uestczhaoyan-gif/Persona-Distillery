# 项目结构与贡献指南

```text
3-人物/
├─ README.md / AGENTS.md              项目入口与 Agent 路由
├─ docs/                              架构、治理、视觉和文档导航
├─ personas/                          人物包；每人一个稳定 person_id
├─ 人物蒸馏/                           来源处理、Schema 和构建脚本
├─ 直接对话/                           快捷入口、加载契约和单人适配层
├─ 圆桌会议/                           多人物讨论协议与评测
├─ 故事推演/                           决策、因果和故事产物
└─ 定题演讲/                           主题研究、提纲和演讲稿
```

人物事实只放 `personas/<person-id>/`；功能协议、Schema、脚本各放对应功能的目录，例如 `圆桌会议/schemas/`、`直接对话/scripts/`。人物蒸馏工具继续归 `人物蒸馏/scripts/`。新增人物必须更新 `02-人物索引.md`，需要中文或简写入口时更新 `直接对话/persona-aliases.json`；稳定 ID 可直接解析。

## 每层放什么

| 位置 | 维护内容 | 不应放入 |
| --- | --- | --- |
| `docs/` | 跨模块设计、治理、视觉、开发指南 | 人物证据副本、会话正文 |
| `personas/<person-id>/` | 来源、证据、记忆、行为规范、评测与 manifest | 功能运行时或 API 密钥 |
| `<功能>/README.md` | 当前能力、使用入口、目录导航 | 把未来命令写成已实现功能 |
| `<功能>/prompts/` | 可执行的 Agent 提示契约 | 多份相互竞争的启动 Prompt |
| `<功能>/schemas/`、`scripts/` | 本功能机器契约和工具 | 跨人物重复材料 |
| `<功能>/docs/` | 详细设计与未来接口 | 用户必须读完才能开始的长说明 |
| `tests/` | 跨模块入口和回归检查 | 真实私人会话 |
| `.persona/`、`sessions/` | 本地配置、预览授权和生成会话 | 未经检查的公开发布材料 |

新功能有真实实现后再创建 `src/`、测试和依赖文件，避免堆空目录。跨模块共享代码至少有两个实际使用方后再抽取；先保持每个模块可独立理解。

## 开发和验证

直接对话入口仅需 Python 3.10+ 标准库，从仓库根目录运行：

```powershell
python 直接对话/scripts/resolve_persona.py --list
python 直接对话/scripts/resolve_persona.py kongzi
python -m unittest discover -s tests -v
```

没有既有本地授权的草稿预览会被拒绝；仅在当前会话已获授权时使用 `--preview`。解析器只输出加载计划，不调用模型。原有人物记忆构建和校验还依赖 NumPy，其工具职责不变。

修改入口时验证四个人物、别名、缺失文件、准入和路径边界；修改资料时另跑对应人物的结构化记忆校验，实际对话质量仍需保留题和人工盲测。

## 发布和迁移

全局视觉、治理和项目蓝图已从根目录移入 `docs/`，人物索引仍保留在根目录。人物包、来源 ID、manifest 和数据索引路径未迁移。旧文档引用应改为新相对链接；运行提示不再依赖文件夹名 `3-人物/`。

原文、私密增强层、完整会话、密钥及 `.persona/preview.local.json` 不得提交。公开的是空白模板；本地预览授权不改变人物发布状态。每次发布明确区分仓库版本、人物包版本和功能验收状态。

当前仓库是 Agent 直读研究预览。CLI、Web、圆桌、故事和语音仍按各自 README 标注的状态推进。
