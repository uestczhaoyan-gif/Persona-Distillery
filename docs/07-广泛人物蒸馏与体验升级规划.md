# 广泛人物蒸馏与体验升级：执行规划

制定日期：2026-10-08。基线：v0.2.0 本地工程预览。

状态：`IN_PROGRESS`（2026-10-08 用户授权执行）。本文件依据项目现状和项目所有者方向制定；按小节点实现、验证、提交并推送 GitHub。每 5 小时调度检查实际额度并续做，记录见 [新规划执行记录](08-新规划执行记录.md)。不因持续开发授权而自动启用付费调用或公开发布人物。v0.2 的历史完成记录继续保留。

## 1. 项目目标与成功标准

把不同年代、领域、文化和生活经验的人物，蒸馏为可交谈、可研究、可参与思想实验的人物包。既建设广泛的公共人物库，也让用户在本地整理自己、熟人和在世人物。人物应有鲜明的注意力、判断方法、情感表达和说话节奏，能够自然回应新问题。

三条主线同时纳入路线：

1. **体验升级：** 减少重复禁令和固定回答流程，保留人物自由判断、追问、幽默、争辩和修正的空间。
2. **构建普及：** 从材料准备推进到完整候选人物包，让用户能够用不同来源构建不同类型的人物。
3. **持续扩库：** 建立至少 60 人的候选池，先完成 12 人库，再扩展至 30 人库；每个完成的人物都有 AI 头像、明确用途和实际试聊结果。

数量指不同人物，不把同一人物的多个版本、空目录、模板或只有提示词的草稿计为完成。公共库规模与用户本地私人库分开统计；不为达到数量目标上传私人人物。

第一阶段成功：现有四个人物体验经过比较验证，私人本地构建路径可用，新增八个人物完成材料、对话、头像和基础评测。第二阶段成功：四种体验具有可运行闭环，公共候选人物库中累计三十人完成构建，并分别标注质量与发布状态。完成构建不自动意味着可公开。

## 3. 对话规则如何修改

### 3.1 从多层限制改为少量底线与人物倾向

现有规范已经要求自然对话，但这些要求散落于全局契约、人物规范、锚点、示例和适配层，叠加后仍可能形成过度约束。修改前先统计实际加载内容与冲突，不能仅凭文件字数判断原因。

| 当前易产生的问题 | 修改方向 | 如何验证 |
| --- | --- | --- |
| 多层反复禁止报幕、列表、引用、旁白 | 集中维护默认呈现原则，允许用户明确要求的形式 | 普通聊天自然；要求列表、引证或戏剧形式时能配合 |
| 每题都找固定“人物切口” | 锚点变为可选注意力，不要求逐条表演 | 陌生题和闲聊中不机械套思想标签 |
| 回答总要给行动建议或追问 | 允许只回应、陪伴、反问、讲故事或暂留问题 | 不再每轮以作业和问题收尾 |
| 每次都解释年代与材料不足 | 在界面/首次入口说明模拟性质；关键误解出现时再澄清 | 当代情境可讨论，不虚构人物真实表态 |
| 不许推演被理解成不许想象 | 允许新推理、比喻、原创故事及情绪表达 | 不把创作写成可核验的亲历、引语或真实关系 |
| 同一种“正确助手”替换所有人物 | 保留有依据的差异、矛盾、偏好和局限 | 去名回答能辨别方法，用户觉得有交流价值 |
| 技术依据占据默认正文 | 研究层按需展开，保留后台回链 | 用户追问依据时可核查，平时不展示卡号 |

保留的核心底线：不冒充真实身份；不伪造原话和经历；不泄漏私人资料；不绕过本地/传播限制；不以人物身份推动现实伤害。其余尽量表达为简短正向偏好，避免把“不准公式化”再变成几十条公式。

### 3.2 目标加载结构

- 全局运行契约：准入、模拟身份、事实边界、工具权限、保存规则。
- 人物核心：材料支持的注意力、价值张力、判断方式、语言节奏；不逐题规定标准答案。
- 人物记忆：证据与情境材料，容量允许时整体读入，否则按需检索。
- 功能适配：仅维护对话、圆桌、故事、演讲之间真实存在的差异。
- 用户偏好：长短、语言、风格浓度和是否展开依据；自然语言即可调整，不要求用户理解参数。

研究模式不另造一套人物，仍围绕当前回答提供依据。界面保持简短可见的“AI 人物视角模拟”标识；CLI 会话入口一次说明；单独导出的文章携带说明，避免脱离界面后失去上下文。

### 3.3 质量实验

固定模型、版本、采样配置和题目，比较 A：通用助手；B：简短人设；C：现有完整包；D：精简契约后的完整包。先用开发题调试，再冻结配置运行独立题。

每个现有人物至少 20 道独立单轮题、5 段至少 6 轮的对话；覆盖闲聊、情绪交流、专业思考、用户反驳、现代条件、来源追问和诱导编造。研究层核验另运行，生成答案时不加载评测预期。已有公开保留题作为回归，新盲评题在冻结提示后另建。

暂定验收：至少两名独立评审；自然度和帮助度中位数均不低于 4/5；相对现有版本的成对偏好至少 60%；无姓名和典故提示时四选一方法辨识率至少 70%；抽查关键人物事实回链准确率至少 90%；评测中伪造人物原话、私密外发和身份冒充等严重失败为 0。报告题量、分歧和不确定性，不能把小样本当普遍证明。阈值可在看结果前调整并记录理由，不能事后降门槛。

自动评审辅助发现问题，不能伪装为独立人工盲评；尚无人工评审时标为 `REVIEW_PENDING`。用户不必逐条审核所有低风险素材，只在合并后的里程碑结果上作判断。

## 4. 人物类型、运行位置与传播权限

### 4.1 产品方向

取消“只有历史公共人物才能私有预览”的类型白名单，改为按材料、执行环境和输出用途判定。不能公开的人物也可以达到很好的本地对话质量；质量等级不应充当传播许可。

本地运行是本项目的产品边界，不是“本地便自动获得材料权利”的法律结论。以下为工程政策设计，具体公开使用仍按材料与地区要求核验。

| 人物/材料情况 | 构建与使用路径 | 网络与传播 |
| --- | --- | --- |
| 历史公共人物，公开材料 | 正常构建；草稿即可显式试聊 | 权利允许的材料可使用声明过的服务；公开发布单独审核 |
| 在世公众人物，公开材料 | 允许构建人物视角；本阶段默认本地受限 | 人物合成与对话本地执行；不发布人物包、可识别生成稿或头像；资料获取使用公开来源，不搜索私人信息 |
| 自己 | 允许自述、作品、问答式构建 | 默认本地；纯本人且无敏感/第三方内容的独立公开版才进入发布审核 |
| 熟人、导师、亲友、同事或已故私人个体 | 允许基于用户有权处理的材料和明确标为用户回忆的描述建立本地草稿 | 本地存储和模型；无分享、远程处理或公开导出通道 |
| 含第三方敏感内容、未成年人等情况 | 提供本地导入、删减、脱敏与整理；按具体内容限制处理 | 强制本地，禁止对外传播；存在侵入性、伤害性用途或无权取得的材料时阻断相应内容 |
| 原创虚构人物 | 支持世界观、设定和原创材料 | 可按创作者权限发布；不冒充真实人物 |
| 受第三方权利约束的虚构人物 | 允许明确标识的研究/本地探索 | 材料和衍生资产的公开许可另审，不因“虚构”自动放行 |

“熟人”不自动拒绝；“上传了文件”也不自动证明资料可用。普通本地草稿采用简明声明，记录材料来源、使用权限、自述/回忆性质及不得传播提示，不一律索取正式授权书。混合材料按片段隔离：有问题的部分等待处理，其余可继续。涉及明确需授权的私人通信、录音等材料，保留针对性确认，不能用普通声明覆盖第三方权利。

不从姓名搜索普通人的隐私画像，不推断缺乏材料的敏感属性。用户回忆可支持“用户记忆中的某人”，不能升级为经独立核验的历史事实；主观回忆与对方本人材料允许并存、标明分歧。

### 4.2 机器执行边界

M1 定义并实施版本化策略，拟新增独立字段：`execution_policy`、`distribution_policy`、`material_basis`、`review_status`。具体枚举在 Schema 设计时冻结；本文件中的字段是设计目标，不能直接写入仍禁止额外字段的 v1 manifest。

- `readiness` 表示质量；`capabilities` 表示已验证的功能；运行策略决定哪些模型和工具可读；传播策略决定是否可导出/分享。
- 受限模式下，蒸馏、embedding、OCR、转写、聊天、头像生成、日志与缓存均走本机。缺少本机组件时提示安装或暂停对应步骤，不能悄悄切云端。
- 公共资料获取与私人数据外发分开：在世公众人物可先下载已知公开资料，再断网构建；熟人资料不向外发送姓名、正文、摘要、图片或检索查询。
- “文件在本地”不等于“模型在本地”。远程 Agent/云模型不能打开受限人物正文、头像参考和摘要；只可处理无敏感内容的开发说明与虚构测试夹具。
- 下游混用多个人物时，整场对话、圆桌、文章和导出继承最严格限制；提炼成摘要不自动解除限制。
- 本地受限人物存于用户选定的非仓库、非云同步目录；应用检查 Git 跟踪、已知同步路径并提示未知同步风险。公共索引不登记私人姓名；本地索引单独维护。
- 禁止受限人物的公开导出、上传、外网服务绑定及公开链接生成；允许本机查看和本地备份，备份继承限制。导出器基于允许清单生成公共包，不直接压缩工作目录。
- 策略由中央检查器在模型调用、文件读取、工具调用和导出前强制执行，不能仅依赖 Prompt 或前端按钮。
- 保存设置只确认一次，变化时再确认；默认不保存完整私聊。撤回/删除覆盖原文、证据、索引、头像、缓存与生成稿，并报告无法代为删除的外部备份。

可以对项目提供的通道落实禁外发并测试；不能承诺阻止用户截图、手工复制或改源码传播。界面清晰告知边界，不能把免责声明当作隔离机制，也不能声称从技术上绝对防止侵权。

### 4.3 兼容迁移

保留稳定 ID 与来源 ID；引入新 Schema 版本和显式迁移命令，支持只读预览迁移结果、备份和回退。旧包缺少执行/传播字段时采用保守默认；已有历史人物预览授权保留原范围，不自动扩展给新增人物。旧解析器必须拒绝不支持的新策略版本，不能忽略字段后放行。

M1 同步更新 AGENTS.md、命令入口、加载契约、manifest/job Schema、构建器和导出器；避免只改文档就宣称已支持私人本地模式。

## 5. 蒸馏闭环与资料深度

统一流水线：选择人物与用途 → 输入材料/访谈 → 来源登记 → 解析和去重 → 候选证据 → 情境与反例 → 人物核心 → 试聊 → 头像 → 审核及版本化。

输入新增“引导式访谈”：用户讲述自己或熟人的习惯、判断、经历和表达，系统追问具体事例并保留“用户陈述”来源类型。材料少时仍可创建明确标为低覆盖的探索草稿，不虚构证据凑数。

按顺序支持：现有 TXT/Markdown → URL/HTML、可提取文本的 PDF、DOCX → 聊天导出和参与者映射 → 扫描 OCR、音频转写与时间戳。解析器必须说明支持范围、失败文件和本地/远程位置。

构建器生成候选内容，不把模型自身知识作为来源。审核视图显示原材料位置、概括、推演、反例与冲突；人工修改保留，增量构建仅重审受影响部分。结构化 JSONL 为构建主数据，Markdown 为可审查视图，避免双份编辑漂移。

检索先测现有词汇方案在同义句、隐含情境和中英问题上的召回，再决定是否增加本地多语言 embedding 与混合检索；不固定每问必须检索。每次回答展开“依据”时区分实际检索记录与回答后补查，不能把事后找到的材料声称为真实生成过程。

公共人物的基础包目标：2—3 个明确用途，约 8 组独立来源见证、25—40 条有效证据、15—30 条不重复情境/判断记忆，覆盖至少 3 类主题和反向材料。数字为检查参考；材料稀少者可低覆盖试用，缺口必须可见，不能以拆章节和改写同一观点凑数。

私人包按真实材料与用户用途评价，不套历史人物来源配额。使用虚构采访/聊天测试工程，不索取真实私人聊天作为开发夹具。

## 6. 扩库批次与人物选择

### 6.1 候选池

建立至少 60 人候选台账，覆盖科学、工程计算、人文思想、文学、艺术、教育、社会实践、商业组织与体育等至少 8 个领域，并关注时代、地区、性别与经验差异。人物使用多标签，不硬塞进单一分类。

每行记录：稳定 ID、身份锚点、人物类型、用途、区别于现有库的方法、来源线索、独立性/权利待核项、运行与传播类别、预计工作量、批次和阻塞原因。候选名单只代表选题，不代表资料已审查。

### 6.2 第一批：4 → 12 人

优先候选八人：墨子、王阳明、达尔文、玛丽·居里、图灵、格蕾丝·霍珀、弗吉尼亚·伍尔夫、泰戈尔。目标是扩充思想对照、科学发现、计算工程、文学与教育经验。构建前逐人核验身份、资料与用途；材料不足可以由同类候选替换并记录原因，无需为名字固定而勉强合成。

以每批两人推进，先小规模确认构建流程，再复用至八人。新增人物均交付可用头像，不能只更新索引。另用“自己、熟人、在世公众人物”三种流程测试本地功能：前两者优先用项目原创虚构夹具；在世公众人物只用公开且非敏感材料、本机处理，不进入公共发布包。

### 6.3 第二批：12 → 30 人

新增十八人，按候选池成熟度选取。每批三人，至少新增两个当前不足的领域；适合进一步评估的例子包括李清照、苏轼、达·芬奇、梵高、简·亚当斯、杜波依斯、杜威、南丁格尔等。其余由资料审核决定，不在此虚列“已可构建”的名单。

每批复盘构建耗时、人工审核时间、证据修正率、头像返工率、盲评表现和与既有人物的同质化。超过两轮修订仍无明确特色或材料支撑的个体转为待补充；推进其他候选，不以批次期限降低质量。

三十人完成后再决定是否扩展至百人、开放社区投稿或多语言版本，避免维护能力落后于扩库速度。

## 7. 每个人物的 AI 头像

每个新增完成的人物必须有一张特征明显、与现有系列协调的 AI 图像。沿用现代编辑插画式肖像，先实际查看鲁迅和费曼现有头像作为风格参考；不把其脸部特征复制给其他人物。

- 通过脸部轮廓、发型、服饰、姿态、色彩和最多一个代表性道具形成区分，不只换背景色。
- 保留表达空间，不要求所有人同一个表情；避免猎奇、民族刻板符号和冒充真实照片。
- 无可靠历史肖像者明确标为艺术想象；私人用户可选择真实参考的风格化图或不对应真实面貌的象征头像。
- 公共可处理材料可用已明确选择的图像服务；受限人物及其参考照片、姓名、提示词只使用本地图像模型。不得为了“每人都有头像”自动外发。
- 暂无本机生图能力时标记 `avatar_pending`，可临时显示占位图进行试聊，但人物不能计入完整交付数量。
- 交付 `avatar-original.png`、1024×1024 sRGB `avatar.png`、`avatar.webp`、最终提示词和元数据；记录实际工具/模型、参考图依据、日期、运行位置与审核结果，不继续假定旧平台界面标签等于当前模型。
- 验收全尺寸、64 像素缩略图及多人联系表，检查是否可区分、裁切合适、无错误文字。工具不直接输出标准尺寸时保留原图并做可追踪标准化。

孔子、庄子的缺图在第一批扩库前补齐。头像风格一致与人物特征鲜明同为验收项，不要求照片式面貌识别准确率。

## 8. 四个应用 Part 的后续实现

### 8.1 直接对话

优先实现简化提示、按需记忆、用户偏好、多轮修正、依据核查、人物切换和本地私人加载。不同模型通过适配器接入；先验证本机 Ollama，再扩展可选服务。云模型只加载允许外发的数据。摘要保存与历史恢复沿用明确选择；长期记忆不能自动把用户私事写入人物公共资料。

### 8.2 圆桌会议

在现有状态机上接入主持器、人物运行器和编辑器。首版三个人物、六回合、一次用户插话；随后测试至少五场不同主题。主持器根据未解分歧选下一位，不强迫吵架或每人等时长。

验收暂停后的在途响应失效、恢复不重复提交、插话影响后续、人物相互回应、分歧不被过早抹平，以及文章每个实质段落可回链回合。真实请求取消与票据拒收分别报告。未证明语义质量时，协议通过不能替代内容通过。

### 8.3 定题演讲

实现主题/听众/时长配置、研究简报、提纲、正文、修订与本地导出。事实研究与人物记忆分层；受限人物使用本地已导入材料，不向外发题目和人物信息。

首版三个人物各做一篇 8—12 分钟目标演讲，按实际口读校准时长。验收中心命题、论证、例子、口头可讲性、人物差异和事实回链。用户要求时先审提纲；不必每个步骤都人为停顿。

### 8.4 故事推演

先做一个人物、三个决策节点、一个结局和一次从节点重开分支。世界事实、人物已知信息、行动、资源、关系和后果分别记录，不能让人物全知或让情节强行奖励其观点。

验收行动有成本、状态前后一致、替代分支产生合理差异、失败能影响下一步，最终文章只对应实际路径。先完成两个不同题材样例，再扩展多人物和分支图。

### 8.5 本地界面与远期能力

Web 首版是绑定本机回环地址的本地应用：人物库、构建向导、审核、聊天、依据查看、四个功能入口、运行位置标识和本地文件管理。受限数据不得走远程 CDN、外部字体、分析上报或远程服务端渲染。私人索引与公共库分开，界面不要暴露工程字段。

声音播放、声音克隆、远程托管、社区投稿、手机端、微调和百人库均属于后续新范围。当前优先文字体验、人物深度和实际图像。未来语音先采用通用讲述音色，独立处理声音授权与本地限制。

## 11. 进度记录、停止条件与交付

每个里程碑维护：状态、输入版本、已交付文件、实际运行命令/模型、测试结果、人工评审、风险、下一个动作和结束条件。状态使用 `PLANNED / IN_PROGRESS / REVIEW_PENDING / BLOCKED / COMPLETE`；不要把预算耗尽或人工未评写成完成。

最低里程碑交付：可运行实现或完整人物包、使用说明、具有辨别力的测试/评测结果、已知限制、回滚方式。纯文档和图像资产更新不要求无意义的代码测试，检查链接、资产和呈现即可。

遇到缺少本机模型/图像/OCR 能力时保留阻塞原因及安装需求；继续不依赖它的工作，不外发受限内容。出现外发绕过先修复再扩库。两轮人物修订无进展则暂停该个体，保留失败证据并更换候选。公开发布始终是独立动作，本地完成不自动推送私人资料。
