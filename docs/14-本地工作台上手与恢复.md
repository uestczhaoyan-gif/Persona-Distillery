# 本地工作台上手与恢复

本指南对应当前工程预览。四种形式都已有实际后端；人物内容质量、真实模型表现和演讲口读时长仍待独立验收。

## 启动与模型准备

在仓库根目录安装 `requirements-dev.txt` 的依赖，运行：

```powershell
python 本地应用/scripts/server.py --port 8765
```

打开 `http://127.0.0.1:8765/home`。工作台只绑定本机地址。已安装的 Ollama 服务和模型由使用者准备；页面不会下载或安装模型。

进入任一工作台，点“检查本机模型”。找到模型后选中并勾选本机服务确认。检查只读取模型列表，真正生成仍需点击对应按钮。服务不可达时先恢复本机服务；无模型时先准备模型，再检查一次。

当前四位历史公共人物都是草稿预览，需明确确认；这不会改变人物包的审核或发布状态。不要把真实私人材料填进这些公共人物工作台。

## 第一次完整操作

| 形式 | 输入 | 运行顺序 | 最终结果 |
| --- | --- | --- | --- |
| 直接对话 | 人物、本机模型、具体问题 | 开始新对话→发送→追问；需要时查看依据 | 自然回答及按需依据，内存会话 |
| 圆桌 | 至少两个人物、议题、目标、回合数 | 创建→开始/继续→必要时插话或暂停→结束→生成讨论稿 | 逐轮记录、讨论稿和依据附录 |
| 演讲 | 人物、主题、听众、目标、时长、资料时间点 | 保存简报→生成人物提纲→生成演讲稿→按需修订 | 演讲正文、来源附录及已校验旧稿 |
| 故事 | 人物、原创处境、规则、目标、资源、世界事实 | 保存→提出选择→选行动→推进后果，重复三次→整理成稿→按需叙事编辑 | 实际路径草稿、时间线、依据、独立叙事稿 |

演讲补充来源是使用者提供的资料，不会自动联网核实。旧稿版本选择只影响阅读和下载，修订仍基于最新稿。

故事资源按每行 `时间=6` 这样的格式填写。隐藏事实只供世界后果处理，不直接变成人物已知事实；时间线可能展示内部因果。替代路径从此前保存点分叉，原路径保留。

## 失败与恢复

- 模型不可用或生成失败：已提交状态保留，修复条件后再点击。页面不自动重发请求。
- 对话失败：输入问题保留，可修改后重新发送；“刷新对话状态”只读取进度。服务重启后内存会话消失，需要重新开始。
- 故事轮询中断：点“刷新路径状态”；或从已有故事重新打开。暂停拒收迟到结果，不保证停止模型计算。
- 演讲修订失败：旧稿保留。版本列表只展示可回链且校验通过的稿件，旧格式缺少索引时会提示缺口。
- 页面刷新/服务重启：圆桌、演讲、故事从工作空间已有作品继续。不要在模型生成中关闭服务；圆桌遗留票据可先暂停再继续。
- 文件手工改动后读取失败：保留文件并检查修改，不把它当成已校验原稿，也不要为了消除提示重写校验值。

## 保存位置与验收边界

圆桌、演讲、故事分别沿用对应模块的 `sessions/`，不写第二份作品库。直接对话只存在服务内存，不自动保存完整聊天。下载保存在浏览器的本机下载位置；公开发布仍需单独审查。

`tests/manual_story_browser.py`、`tests/manual_lecture_browser.py` 是独立的原创合成验收服务器，使用临时目录与固定输出。它们用于检查交互，不能代表真实人物或模型效果，也不是正式使用入口。
