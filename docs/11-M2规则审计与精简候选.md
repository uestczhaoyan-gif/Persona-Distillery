## 实际加载与发现

`resolve_persona.py` 顺序为 manifest → Agent 契约 → 人物规范 → 核心锚点 → 示例 → 档案 → 证据 → 情境记忆 → 人物卡 → 可选直接对话适配。只有孔子和庄子有专用适配。`compile_context` 还加入模拟身份与禁网头；`ChatSession.send` 每轮加入自然/研究模式提示。私人 v2 是独立读取路径，本次不改。

| 位置 | 可核查问题 | 候选处理 |
| --- | --- | --- |
| 全局契约 C、四份规范、两个适配 | 重复不列卡号、不用模板、不复读、不要例行追问 | 共用候选集中说明；材料与样例只作倾向参考 |
| 孔子适配“对话位置”与“输出校准” | 禁止主动引用经典，但启动样例引用经典 | 候选不载入旧适配；无需固定迎宾话，引用真实性仍需证据 |
| 孔子/庄子规范“研究层”与加载器 | 写“才读取”证据，与启动完整加载冲突 | 读取由运行器负责，研究层表示按需解释依据 |
| 孔子规范“交流气质/回答行为” | 先赞同再指出责任；先给行动再解释 | 改为可自由回应，无需每轮安排练习 |
| 鲁迅锚点“回答时的优先级” | 细节→代价→参与者→行动像流程 | 共用契约明确锚点是可选倾向，允许欣赏和陪伴 |
| 庄子适配“浓度” | 一个回答至多一个主要比喻是硬数量约束 | 随实际帮助选择，不以数量约束代替判断 |
| 费曼规范“解释与陪练” | 陪练提问偏好可能泛化到所有交流 | 明确用户要陪练才邀请预测，直答和安静推导同样有效 |
| 全局契约 B | 可按需读取带评分预期的 evaluation | 实验编译路径必须隔离评测页；不只靠文字提醒 |
| CLI 编译禁网头 vs 包内联网建议 | 工具能力与材料建议不一致 | 候选明确实际运行器决定工具权限 |

上述是提示结构的风险分析，不证明它们已经导致某种真实模型失败。现有规范本来也明确反对固定模板；不能把精简写成推翻全部旧设计。
