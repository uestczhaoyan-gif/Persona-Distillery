# v0.2 工程完善计划与结束条件

起始日期：2026-10-07（Asia/Shanghai）。基线：`ebb17c3`，v0.1.0 研究预览。

用户已授权下载、持续完善、分阶段验证和推送 GitHub。沿用项目蓝图和开源实现路线，先贯通可复现的本地工程能力；四个人物的事实、证据、发布状态和能力开关不因工程测试而升级。

## 固定工作范围

| 顺序 | 可交付成果 | 验收条件 |
| --- | --- | --- |
| M1 | 仓库校验命令、依赖说明、跨平台 CI | 四个人物的 Schema、入口、来源回链、索引一致性通过；既有回归通过 |
| M2 | 本地中文/英文记忆检索、doctor 和上下文编译 | 确定性排序、无关查询、来源定位、人物隔离、受保护路径、上下文容量边界经过测试 |
| M3 | 最小本地对话 CLI | 显式选择 Ollama 本地适配器；错误清晰；默认不保存对话；研究层可审计；离线桩验证完整会话 |
| M4 | 本地上传蒸馏闭环 | 校验 job；支持 TXT/Markdown；来源登记、去重、切分、文件隔离、审核暂停、恢复和增量变更检测；不自动创造证据或发布人物 |
| M5 | 圆桌状态管理原型 | 创建/发言申请/原子提交/暂停/恢复/结束；拒绝迟到响应、重复回合、非法迁移；轮数上限；导出逐轮记录 |
| M6 | 可复现验收与文档 | 全回归、四个人物校验、CLI 烟测通过；中英文入口准确；明确未验证项；所有完成部分已推送并核对远端 SHA |

依赖顺序为 M1 → M2 → M3；M4、M5 各自独立，但顺序执行以便审查。当前工程不包含 Web、语音、微调、自动网络采集、PDF/OCR/音视频导入、付费模型实验或人物公开发布。它们保留在既有路线中，不加入本轮待办。

## 验证与提交规则

- 每次实现先写最小、具有辨别力的行为测试，覆盖正常流程及关键失败边界。
- 使用原创/虚构夹具；不向 Git 提交完整真实会话、私密上传、密钥、受保护全文或本地增强层。
- 每个里程碑针对性验证和回归通过后单独提交，正常推送到 `origin/main`；拒绝强推。若远端出现新提交，先读取并协调再继续。
- 记录真实命令与结果；桩模型通过只证明工程协议，不证明人物对话质量。
- 不购买额度，不消耗重置券，不因测试配置自动联网调用模型。

## 续做与停止合同

实际 Codex 额度由账户查询工具读取；5 小时是额度窗口，不是保证可连续运行的时长。每 5 小时定时续跑前检查 5 小时及周额度，长期工作还在里程碑边界保存检查点。额度不足时保留未完成状态等待调度；不得把额度不足标成工程完成。

结束标志只允许以下两种，写入根目录 `PROJECT_STATUS.md`：

1. `ENGINEERING_COMPLETE`：M1–M6 验收完成且提交已同步 GitHub；生成 `docs/06-验收报告.md`，暂停续跑自动任务。
2. `STOPPED_BLOCKED`：真实外部阻塞连续三个调度周期无法进展，或已达到 12 次定时续跑检查；保留已完成成果、未完成项、原因及解锁条件，暂停自动任务。该标志不代表全部功能完成。

没有新范围自动扩张。人物去名盲评、真实模型质量、资料权利审查须人工验收，不用工程通过替代。定时任务 ID 为 `persona-distillery-5`；计数、额度和运行检查点保存在不提交的 `.work/autonomous-checkpoint.json`。
