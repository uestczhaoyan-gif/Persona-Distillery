# 项目蓝图：把人物材料变成可用的思考伙伴

## 一、先定义产物，而非先囤资料

每个人物体应当同时包含五层，缺一层都会失真：

| 层 | 回答的问题 | 主要载体 |
| --- | --- | --- |
| 事实与生平 | 他在何时何地做过、说过什么？ | 时间线、来源、证据卡 |
| 思想与知识 | 他相信什么、使用什么概念、在哪些议题有经验？ | 观点图谱、主题卡 |
| 决策与方法 | 他怎样看问题、权衡什么、会追问什么？ | 决策案例、启发式规则、反例 |
| 表达与交互 | 他如何组织语言、语气和节奏如何？其时代语言或翻译腔怎样进入现代对话？ | 风格说明、时代语言模式、少量示例 |
| 情境与记忆 | 面对具体问题时，他怎样行动、失败、修正并迁移？ | `08-context-memory.md`、情境案例 |

不要以“模仿口头禅”替代事实、思想、方法和情境记忆；表达层的权重应最低，且不得伪造引语。

## 二、人物分类：用标签而非硬分文件夹

一个人常跨多个领域，因此人物目录采用稳定 ID，分类放进人物卡和全局索引。推荐标签维度：

| 维度 | 示例 |
| --- | --- |
| 领域 | 科学、工程、商业、艺术、哲学、教育、政治、体育 |
| 角色 | 研究者、创始人、实践者、管理者、教师、作家 |
| 时代/地区 | 1910s--1950s、当代、中国、欧洲、跨文化 |
| 材料状态 | 公开充分、碎片化、需授权、已核验 |
| 可用能力 | 问题拆解、创作批评、科研方法、领导力、写作、伦理推理 |
| 风险级别 | 低、中、高（在世/私密/争议/高风险领域） |

目录命名建议：`personas/ada-lovelace/`、`personas/张三-2026/`。若同名或不同人生阶段，可在 ID 中加年代或版本，但不要把不同人物混在同一目录。

## 三、资料来源与处理优先级

优先顺序：本人著作/原始演讲和访谈 > 有原始音视频的对话/书信 > 可靠传记与机构档案 > 高质量转述 > 评论。

不同媒介的关键元数据：

- **书、文章、论文：** 版本、出版社/DOI、章节和页码、出版年、译本与原文的关系。
- **访谈、对话、播客：** 参与者、主持方、发布日期、完整视频/音频链接、时间戳、是否经剪辑。
- **演讲、课程、视频：** 活动名称、场合、受众、录制日期与发布时间、字幕来源。
- **书信、日记、聊天记录：** 创建日期、参与者、授权状态、私密等级、去标识化状态。
- **他人转述：** 转述者、与人物关系、转述链、是否能反查一手材料。

原始文件只放入 `raw/` 或在台账记录外部地址；清洗后的片段放到 `processed/`。任何切分片段都必须保留 `source_id` 和定位信息，不能脱离出处。

## 四、标准工作流

这套工作流既可以人工完成，也可以通过 [`人物蒸馏`](../人物蒸馏/README.md) 的网络搜索或用户上传模式自动执行。自动化仍须遵守相同的来源、证据和评测标准。

```mermaid
flowchart LR
  A[定义人物与目标] --> B[建来源台账]
  B --> C[获取与转写]
  C --> D[清洗、切分、标注]
  D --> E[证据卡和观点/决策图谱]
  E --> I[情境记忆：问题、动作、失败、修正]
  I --> F[人物记忆对话原型]
  F --> G[评测、人工校对、版本发布]
  G --> H[使用日志与持续纠错]
  H --> B
```

### 1. 定义问题

在收集前写清楚："我希望它在哪三类问题上帮我？" 例如："用某科学家的研究策略帮助我审视一个实验设计"，而不是泛泛地"和他聊天"。这会决定材料取舍和评测题。

### 2. 建来源台账

每找到一份资料，先登记到 `01-sources.csv`，再处理。台账是项目的地基：它记录可信度、版权/授权和覆盖主题，避免反复下载或把低质量名言混入语料。

### 3. 清洗、切分与标注

转录中保留说话人、段落/时间戳及上下文。切成能独立理解的小片段（通常 150--500 字），但不能打断论证。给片段添加主题、年代、材料等级、是否直接引语和敏感级别。

### 4. 提炼证据卡

每条卡片只表达一个可检查的观点、事实或决策案例，带原文摘录与来源。"人物设定"要由卡片归纳出来，而不能反过来拿设定选择证据。

证据卡完成后，再建立 `08-context-memory.md`：把观点放回人物真正遇到的问题，记录其可观察动作、失败或张力，以及迁移到新问题时的边界。情境记忆不能把同一观点换七种说法来虚增数量，也不能按章节连续复述受保护作品。

### 5. 对话引擎

首选工作方式：先让通用模型读入人物规范、原创对话示例、证据卡和上下文能够容纳的情境记忆，把它们内化为记忆与注意力倾向。人物包较大时，把证据与情境记忆检索作为模型可自主调用的记忆工具，而不是每轮强制执行的前置流水线。默认回答以人物视角直接、连贯地说话；历史事实仍受证据约束，依据、反例和引用只在用户问"为什么这样说？"、"依据是什么？"或确实需要回忆核验时展开。

这形成两个层次：

| 层次 | 用户看到的内容 | 系统实际做的事 |
| --- | --- | --- |
| 对话层（默认） | 像与一个有鲜明方法和语气的人聊天 | 人物记忆参与推理；模型按需决定是否检索 |
| 研究层（按需） | "这句话依据什么？还有别的看法吗？" | 展示证据卡、出处、相反材料和推演边界 |

不在默认每段话后附 `E-xxxx`、链接或"综合概括"标签；这些会打断沉浸感。但模型仍不得把推演伪装成确定的个人经历或逐字原话。可以自然地说"就我已有的材料而言，我会先……"、"这更像是一种推断"或"这件事我没有足够把握"。

可将人物规范写成如下顺序：

1. 先把人物材料当作记忆理解，而不是逐条等待调用的规则；
2. 根据用户状态和问题，自主选择怎样展开，不执行固定输出模板；
3. 历史事实、原话和生平需要证据，新的分析与推理可以自由综合；
4. 不把“我不知道”变成固定仪式；在事实缺口确实影响结论时再自然说明，同时让人物的思考方法继续工作；
5. 只有用户要求核验时才展开证据层，不要制造人物"原话"。

### 6. 评测和版本

为每个人留出从未放入提示词的测试问题，至少包括：事实核验、观点辨析、场景迁移、无依据诱导、时间穿越、敏感问题。每次材料或规范变动都重跑评测，结果记入 `04-evaluation.md`。

## 五、什么时候考虑微调

只有在以下条件均满足时才考虑：资料权利清楚；已有稳定的高质量问答/编辑样本；RAG 已解决事实引用但仍缺少稳定表达或任务格式；有独立测试集与回滚方案。

微调适合固化格式、措辞和工作流，不适合解决知识更新、出处追踪或少量资料下的"像不像"。人物项目的大部分价值，通常来自证据库与评测而不是微调。

## 六、它可以做什么

| 用法 | 有价值的输出 | 质量门槛 |
| --- | --- | --- |
| 沉浸式有出处对话 | 默认自然地以人物框架讨论；用户可随时展开依据 | 中 |
| 苏格拉底式陪练 | 按其常见追问拆解你的论证 | 中 |
| 决策复盘 | 把真实历史案例映射到你当前选择 | 高 |
| 多人物圆桌 | 比较不同框架的共识、冲突和证据 | 高 |
| 定题演讲 | 人物围绕领域主题自主立论、联网核验事实并形成可讲述的长文 | 中高 |
| 阅读助手 | 从其概念体系解释原文、标注分歧 | 中 |
| 个人知识传承 | 经授权记录导师/家人的经验与故事 | 很高 |

最有成长价值的用法不是让它替你作决定，而是让它指出你遗漏的变量、要求你澄清假设、再把结论还给你自己判断。

四个基础体验共用人物包，但运行方式不同：直接对话重视即时互动；圆桌重视人物之间的真实分歧；故事推演重视选择与因果；定题演讲重视完整立论、备课和口头表达。人物选择后由后台编译人物包和当前功能适配层，不要求用户粘贴启动提示。各功能可以按需建立临时事实简报，但简报不并入人物历史记忆；直接对话的封装与联网设计见 [`直接对话/02-运行时封装与联网策略.md`](../直接对话/02-运行时封装与联网策略.md)，演讲协议见 [`定题演讲/README.md`](../定题演讲/README.md)。
