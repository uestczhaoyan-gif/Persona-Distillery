# 直接对话运行时封装与联网策略

本文记录后续 CLI/Web 运行时要实现的行为。当前 Agent 已有 [快捷入口](命令入口.md) 和 [加载契约](prompts/agent.md)，用户用简短入口选择人物；独立模型调用和持久化会话运行时尚未实现。

## 一、触发依据是会话状态，不是口令

运行时以用户选中的稳定 `person_id` 和功能 `mode` 建立会话：

```json
{
  "person_id": "kongzi",
  "mode": "direct_chat",
  "package_version": "0.3.0",
  "network_policy": "facts_only",
  "research_mode": false
}
```

“我想和孔子交流”“开始”“请问一个问题”都只是普通用户发言，不承担加载人物的职责。界面选择、CLI 参数或 Agent 命令负责设置 `person_id`。不要用关键词、正则或模型猜测从第一句话决定人物；显示名存在歧义时必须由用户选择稳定 ID。

## 二、后台上下文编译

每次创建会话，运行时在后台按固定层次编译上下文：

```text
直接对话功能契约
  + manifest 与准入状态
  + 人物规范、核心锚点和行为样本
  + 可容纳的人物长期记忆
  + 直接对话/personas/<person-id>.md 可选适配层
  + 当前会话摘要
  + 本轮可选事实简报
  + 用户原始发言
```

直接对话适配层最后加载，只能调整本功能的入场、可见格式和语言浓度，不能改写来源、人物历史或思想证据。圆桌、故事和演讲使用各自的功能适配层，不继承单人对话的界面格式。

后台提示不得出现在聊天记录中。前台第一条内容就是人物对用户发言的回应；系统可以在人物卡或会话顶栏显示人物名称和版本，不让模型正文重复承担界面标识。

## 三、三种入口

| 阶段 | 用户操作 | 后台工作 |
| --- | --- | --- |
| 当前 Agent 原型 | `/孔子` 或 `人物 孔子` | 项目指令路由，解析器校验，Agent 读取人物包和适配层 |
| 最小 CLI | `persona chat <person-id>` | 校验准入、编译上下文、连接本地/API 模型 |
| Web/桌面界面 | 点击人物卡后直接输入 | 程序持有会话状态，用户不可见启动提示 |

现有 `/persona kongzi` 等入口只负责显式选择人物；约定的“我想和孔子交流”也可选择人物，但普通句子中提到人物名不触发切换。客户端原生命令、未来 CLI 和 Web 应复用别名表与加载契约。

## 四、默认关闭搜索，按需建立事实简报

自然对话的主体是人物长期记忆与人物自己的推理。联网只解决外部事实缺口，不搜索“这个人物会怎么想”，也不把网络评论替代为人物立场。

建议支持三个策略值：

| 值 | 行为 |
| --- | --- |
| `off` | 本会话不发起网络请求，只接受用户提供的事实 |
| `facts_only` | 默认不请求网络；用户明确要求核验，或缺失的当前事实会实质改变判断时，临时搜索事实 |
| `research` | 用户主动进入研究层后，可检索来源、原话、反例和当前事实，并显示审计结果 |

直接对话默认 `facts_only`。它在没有触发条件时与 `off` 相同，不代表每轮都搜索。私密人物、上传材料和本地增强层还必须服从更严格的数据策略；联网能力不能把本地原文或私人会话发送出去。

## 五、联网触发与禁止触发

可以触发一次事实搜索：

- 用户明确说“查一下现在的事实”“请联网核验”；
- 问题依赖人物身后的事件、数字、制度或技术状态，而且错误事实会改变分析；
- 用户要求严格来源审计或定题演讲需要当前数据。

不应触发搜索：

- 只为了寻找别人如何评价该人物；
- 只为了给人物判断增加链接和权威感；
- 用户已经给出足够的假设条件，可以直接进行思想实验或条件推理；
- 只是因为人物去世较早，便例行确认所有现代词汇；
- 为每轮回答机械检索固定数量的片段。

事实缺口是否会改变结论不明确时，可以先问一个简短问题，或明确采用用户给出的条件继续推理。

## 六、事实简报与人物记忆隔离

搜索结果经过来源筛选、去重和事实抽取后，只形成当前会话的临时 `fact_brief`：

```json
{
  "brief_id": "FB-YYYYMMDD-001",
  "as_of": "YYYY-MM-DD",
  "question": "本轮需要核验的事实",
  "facts": [
    {
      "claim": "经过核验的简明事实",
      "source_url": "https://example.org/source",
      "source_date": "YYYY-MM-DD",
      "confidence": "high"
    }
  ],
  "disagreements": [],
  "expires_on": "YYYY-MM-DD"
}
```

人物运行时收到的是“由本场研究提供的当前事实”，然后依据人物已有的注意力、价值和推理方式解释。事实简报：

- 不写入 `02-evidence.md`、`08-context-memory.md` 或永久索引；
- 不伪装成人物生前知道的内容或真实意见；
- 默认不在自然回答中展示检索过程；用户要求依据时再展开；
- 会话结束后按配置删除或只保留不可逆的事实摘要与来源记录；
- 只有经过正式增量蒸馏和人工审核，才可能进入人物长期记忆。

## 七、不同功能分别决定联网默认值

| 功能 | 建议默认值 | 原因 |
| --- | --- | --- |
| 直接对话 | `facts_only` | 以人物推理为主，只补决定结论的事实 |
| 圆桌会议 | `facts_only` | 需要联网时先生成所有人物共享的中立简报，避免各自得到不同事实世界 |
| 故事推演 | `off` | 世界状态应由前置条件和因果引擎控制；历史/地理核验按节点临时开启 |
| 定题演讲 | `facts_only`，可由用户开启 `research` | 当代主题常需数据，但材料只充当备课事实，不并入人物记忆 |

这张表是跨功能建议，不替代各子项目自己的运行协议。各功能可以改变显示来源、主持方式和事实简报的生命周期。

## 八、记录与审计

运行时应在后台记录：人物包版本、功能适配层版本、模型与提供方、实际网络调用、使用过的 `brief_id`、是否进入研究层。自然回答默认隐藏这些信息；“查看依据”只展示真实使用过的网络事实和事后人物记忆审计，二者要明确区分。

远程 API 启动前应告知会发送哪些人物摘要和会话内容。密钥、原始私人材料、`research.local/raw/` 和未授权本地文本永不进入提示或日志。
