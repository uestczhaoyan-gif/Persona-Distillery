# 直接对话：与一个人物视角自然交流

开始对话见 [使用方法](使用方法.md)：在已加载项目指令的 Agent 中发送 `/孔子`，若客户端拦截斜杠则使用 `人物 孔子`。所有人物仍按 manifest 检查准入，已有本地预览授权可复用。

| 目录或文件 | 职责 |
| --- | --- |
| `命令入口.md`、`persona-aliases.json` | 人物选择与别名 |
| `prompts/agent.md` | 唯一的 Agent 加载与回答契约 |
| `personas/` | 本功能专用适配层，不存人物事实副本 |
| `scripts/resolve_persona.py` | 只读加载计划与准入检查，非聊天运行时 |
| `scripts/persona.py` | 本地 `list / doctor / search / context / chat` CLI，见 [使用说明](docs/本地工具.md) |
| `_template/` | 会话与本地预览配置的空白模板 |
| `docs/CLI设计.md` | 完整目标接口和已实现边界 |

人物选择、后台提示封装和按需联网设计见 [运行时策略](02-运行时封装与联网策略.md)。

直接对话是项目的基础交互：用户从人物卡选择一位人物，像普通聊天一样提问、追问和切换话题。人物选择是运行时状态，不要求用户背诵启动口令。小型人物包在会话开始作为记忆整体读入；大型人物包把检索作为模型可自主调用的记忆工具。前台默认只显示自然回答，不展示检索日志、编号和引用。

联网默认使用 `facts_only`：没有触发条件时不发起网络请求；只有用户明确要求核验，或缺失的当前事实会实质改变判断时，才建立与人物长期记忆隔离的临时事实简报。网络只补事实，不搜索“这个人物应该怎么想”。

用户随时可以问"为什么这样想？"、"依据是什么？"或"有没有相反材料？"，对话才切换到研究层，解释本次回答的材料与推演边界。

## 会话原则

- 人物视角不是本人：不伪造其私人回忆、当代表态或逐字原话。
- 先回应真正的问题，再自然地追问、反问或提出不同看法；不要把每次交谈写成资料报告。
- 资料不足时坦率说明，而不是用人格表演填补空白。
- 经用户明确确认后，才把有价值的对话摘要和错误案例写入对应人物的 `05-dialogue-log.md`；默认会话只读且不保存完整私聊。

## 最小界面

人物卡、头像、对话历史、输入框，以及按需显示的 `为什么这样说？` / `查看依据` 按钮即可。详细行为规范见各人物的 `03-persona-spec.md`。

加载人物时先读取其 `manifest.json`。`draft` 只允许构建者私有预览；正常用户至少需要 `chat-ready`，并且 `capabilities.direct_chat` 必须为 `true`。

人物在不同功能中的呈现形式可以不同。若存在 `personas/<person-id>.md`，直接对话运行时在人物包之后最后加载它；该文件只负责单人交谈的入场、说话人标签和正文形态，不进入圆桌、故事或演讲。

## v2 本地包接入进度

`local_package.py` 是内部只读接口，读取外部非同步私人库中的完整 `manifest.v2.json` 包。六类人物使用相同的显式预览规则；先验证策略和路径，再读取有界上下文，默认不含日志。它没有上下文导出 CLI；调用者必须先验证实际本机处理器，不能将返回内容上传到云 Agent。M1.4c 已提供 `local_chat.py` 内部只读会话，逐轮复核本机模型元数据与包哈希；M1.5a 已提供独立终端命令 `scripts/local_persona.py`，见[私人本地预览](docs/私人本地预览.md)。原有快捷入口仍按旧协议工作。
