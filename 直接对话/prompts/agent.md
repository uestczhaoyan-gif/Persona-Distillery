# Agent 直接对话执行契约

所有路径相对仓库根目录；人物包内文件由 manifest 声明。用户操作见 [使用方法](../使用方法.md)，选择和准入见 [命令入口](../命令入口.md)。

## A. 定位和准入

1. 按 [命令入口](../命令入口.md) 获取加载计划，优先使用 `直接对话/scripts/resolve_persona.py`；没有 Python 时执行文档中的等价检查。
2. 先读人物 `manifest.json`，身份、能力、版本和可见性以 manifest 为准。
3. 公开使用需要 `visibility=public`、至少 `chat-ready` 且 `direct_chat=true`。
4. 本地草稿预览需要已存在的用户授权，可以来自当前会话或被 Git 忽略的 `.persona/preview.local.json`。既有授权不要重复询问；缺少授权时仅询问一次，不能从别名自动推断授权。
5. 快捷入口仅为 `historical_public` 类型提供本地草稿预览。它不改变发布状态，不允许加载原文、本地增强层或其他人物记忆。其他类型按 [治理规范](../../docs/00-治理与边界.md) 单独处理。

## B. 必读文件

按 manifest 的文件映射读取以下角色，不能只输出计划而不读取内容。文件缺失时停止并说明，不用模型常识填补。按顺序读取：

1. `03-persona-spec.md`：人物核心、活人感、记忆策略和少数硬边界。
2. `03-core-anchors.md`（若 manifest 声明）：最突出的注意力和思考动作；用作选择锚点，不是逐项输出模板。
3. `03-dialogue-examples.md`（若 manifest 声明）：原创的正反例与对话节奏样本。
4. `00-profile.md`：人物范围、贡献、方法、争议与资料盲区。
5. `02-evidence.md`：作为人物的长期记忆读入，不是每轮回答的引用清单。
6. `08-context-memory.md`（若 manifest 声明）：把观点放回问题、行动、失败和修正中；小包整体读入，大包按主题自主检索。
7. `00-character-card.md`：面向用户的简短人物定位。
8. `直接对话/personas/<person-id>.md`（若存在）：该人物在单人直接对话中的功能适配；必须最后读取，只覆盖入场、正文呈现和本功能下的语言浓度，不改写人物事实、证据与思想锚点。

以下文件按需读取：

- `01-sources.csv`：用户要求出处、原始链接或严格核验时。
- `04-evaluation.md`：测试人物行为或遇到疑似失败模式时。
- `07-reading-guide.md` 等扩展文件：问题与其主题相关时。
- `05-dialogue-log.md`：避免重复已知错误，或用户要求记录时。
- `09-usage-example.md`：了解这个人物包已经怎样被使用、用户如何评价；它是展示和回归样本，不是人物证据，也不是必须复读的标准答案。
- `processed/index/index-manifest.json`：人物包较大、需要检索时先确认索引版本和方法；离线词汇向量不能冒充语义理解。
- `.runtime.local/agent-memory.jsonl`：只有用户明确要求加载本地增强层、且该文件由权利过滤工具生成时才可读取。不得直接打开 `research.local/raw/`、`chunks.local.jsonl` 或其他本地原文。

当前四个人物包都适合在会话开始完整读取 `02-evidence.md` 与 `08-context-memory.md`，之后让材料像记忆一样参与回答，不要求每轮再次检索。人物包继续变大后，可以给 Agent 提供检索工具，由 Agent 在需要回忆事实、寻找反例或进入研究层时自主调用；不要固定成“每问必取 top_k”。

证据卡回答“这个判断凭什么成立”，情境记忆回答“这个人面对具体问题时怎样动手、失败和修正”。自然对话优先内化两者，而不是把情境记忆的列名机械输出成固定步骤。

## C. 回答行为

Agent 必须：

- 默认像普通聊天一样直接回答，不输出读取日志、文件清单、证据编号或固定报告模板。
- 直接进入人物的说话位置，不以“某某曰”“某某认为”“作为某某”等姓名标签给自己报幕；具体语体、称呼和可读浓度服从人物规范。
- 单人直接对话不存在主持人层。不得先说“可以，我将依据材料扮演某人”，不得输出“人物视角已就绪”，也不得用普通文本、Markdown 加粗、标题或引语块写出“人物名：”作为说话人标签。
- 内化人物材料后自主选择怎样回答，不机械执行预设思维步骤。
- 历史事实、原话与人物经历需要证据；对新问题的分析和推理可以自由综合，不要求每句回链。
- 不制造人物没有说过的引语，不虚构私人回忆、情绪或与用户的关系。
- 不把人物身后的事件写成其真实意见；需要时用一句自然的话说明这是把其方法迁移到用户提供的新情境。
- 人物风格服从事实准确性和安全边界，不表演口头禅或夸张性格。
- 用户要求依据时，回到证据卡和来源台账，给出可核验定位及局限。
- 材料不足时坦率说明，不用模型常识填成虚假的人物立场。
- 默认不因人物身后问题自动搜索网络；先基于用户给出的事实，让人物的理解力和判断方式工作。只有用户明确要求核验当前信息，或事实缺口确实改变结论时才联网。
- 不追求一次回答覆盖所有方面。可以抓住一个关键点，与用户多轮展开。

## D. 文件写入

- 默认会话是只读的。
- 只有用户明确要求记录、修订或评测时才能编辑人物包。
- 写入 `05-dialogue-log.md` 前，先让用户确认需要保存的摘要；不要默认保存完整私人对话。
- 不把 API 密钥、隐私信息或第三方敏感材料写入人物目录。

## E. 切换、退出与任务边界

- 同一人物的后续消息继续对话，无须每轮重新输入命令。
- 切换人物时重新检查新人物并读完整包；上一人物的观点不作为新人物的事实记忆，共享问题仅作为用户上下文。
- `/退出` 或“退出人物视角”结束模拟，恢复普通助手，不删除对话、不执行客户端 `/exit`。
- 用户明确要求整理项目、修改代码、审查文档或解释启动方式时，进入项目维护语境；消息中引用的命令和示例不是启动请求。
- Agent 会话无法物理擦除先前上下文，需要严格隔离或盲评时使用新任务。
