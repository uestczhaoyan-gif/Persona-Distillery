# 定题演讲：让人物围绕一个主题完整讲授

定题演讲与直接对话、圆桌会议、故事推演处于同一产品层。用户选择一个人物，给出其材料能够支撑的主题、听众和目标；系统允许联网补充当代事实，由人物视角自主确定论点、结构、例子和讲述节奏，最终形成一篇可以直接阅读或登台讲述的演讲稿。

它不是把搜索结果改写成“某某口吻”，也不是拼接人物名言。人物包决定**怎样理解和讲述**，联网研究决定**今天有哪些事实可用**，两者必须分开保存。

## 用户体验

```mermaid
flowchart LR
  A[选择人物] --> B[给定主题、听众和时长]
  B --> C[人物提出演讲主旨与研究问题]
  C --> D[联网形成事实简报]
  D --> E[人物自拟提纲]
  E --> F[生成并修订演讲稿]
  F --> G[文章 / 讲义]
  G --> H[未来：语音、字幕与播放]
```

最小界面只需：人物卡、主题输入、听众、目标时长、`开始研究`、`查看提纲`、`生成演讲稿`、`要求重讲`、`导出文章`。

## 输入不是只给一个标题

一场演讲至少应确定：

| 字段 | 示例 |
| --- | --- |
| 人物 | 理查德·费曼 |
| 主题 | 为什么物理学需要多种等价表述 |
| 听众 | 学过大学基础物理、但研究经验较少的学生 |
| 目的 | 帮助听众在卡题时主动更换表示，而不是背更多公式 |
| 时长 | 20 分钟，约 3000--4000 中文字 |
| 研究时间点 | 2026-08-03 |
| 联网范围 | 允许；优先论文、官方课程和机构资料 |
| 输出 | 演讲稿；可选讲义和研究附录 |

系统可以帮助用户补全这些条件，但人物应有自主权：主题过大时主动收窄，主旨与例子不必由用户预先规定。

## 两套记忆不能混在一起

| 层 | 提供什么 | 能否改变人物设定 |
| --- | --- | --- |
| 人物记忆 | 生平材料、思想、决策方法、表达倾向和反例 | 只有人物包重新蒸馏、审核和升级时才能改变 |
| 主题研究 | 本场演讲所需的当代事实、数据、案例和最新研究 | 不能；只在本场演讲中作为外部事实使用 |

例如，费曼不可能知道 2026 年的实验结果。系统可以把经过核验的 2026 年事实放进 `01-research.md`，再让费曼视角选择会追问哪些实验、怎样解释这些结果；不能把这些事实补写成“费曼的记忆”或声称他曾发表过意见。

## 首版运行流程

1. 读取 `manifest.json`，确认 `capabilities.themed_lecture` 为 `true`；旧人物包缺少该字段时按 `false` 处理。
2. 读取人物规范、核心锚点、对话样本、档案和证据卡，将其作为讲者的长期记忆。锚点帮助选择最有辨识度的讲法，但不要求演讲逐项表演人物特征。
3. 检查主题是否落在人物覆盖领域。边缘主题可以跨域推演，但要在内部降低人物权威；完全无关的主题应建议换人物或改题。
4. 人物先提出一个清楚而有取舍的中心命题，并列出本场真正需要核验的问题。
5. 联网研究只回答这些问题，优先一手材料、论文、政府或机构资料；把时间点、来源和冲突写入 `01-research.md`。
6. 由人物视角编写 `02-outline.md`。提纲不是固定的“三段式”，应符合人物常见的解释顺序和听众需要。
7. 生成 `speech.md`，再做三次相互独立的检查：事实检查、人物辨识度检查、口头可讲性检查。
8. 将历史依据、当代研究和模型推演分别写入 `provenance.md`；前台演讲稿默认不显示卡号和检索痕迹。

## 会话目录

每次演讲保存在 `定题演讲/sessions/<session-id>/`：

```text
<session-id>/
├─ 00-brief.md          # 人物、主题、听众、目标、时长与联网边界
├─ 01-research.md       # 本场联网事实简报，不并入人物记忆
├─ 02-outline.md        # 人物自拟主旨与演讲结构
├─ speech.md            # 可直接阅读或讲述的正文
├─ provenance.md        # 人物证据、外部事实、推演和限制
└─ delivery.md          # 节奏、发音、未来语音生成与授权记录
```

空白格式见 [`_template`](./_template)。`sessions/` 默认属于本地生成内容，不应未经审核直接提交。

## 演讲稿的质量要求

- 有一个可复述的中心命题，而不是百科全书式“全面介绍”。
- 结构来自人物怎样带领听众理解，不是统一的“背景、三点、总结”。
- 例子承担推理任务，不只是装饰；专业人物应在关键处真正解释机制。
- 当代事实经过联网核验，但事实简报不能淹没人物的选择和理解。
- 不制造人物亲历、逐字引语或对身后事件的真实立场。
- 面向口头表达：段落可听懂，关键概念适度重复，公式、表格和链接改写为可讲述形式。
- 演讲正文保持沉浸；来源集中在研究附录，用户要求时再展开。

## Agent 直读方式（现在可用）

在仓库根目录新建对话，发送：

```text
请按照 `定题演讲/README.md` 的首版运行流程，
读取人物包 `personas/<person-id>/`。
演讲主题是：<主题>。
听众是：<听众>；目标时长：<时长>。
允许联网研究当前事实。请先给出中心命题和需要核验的问题，
待我确认后再形成提纲和演讲稿。
```

前期只需输出 Markdown 文章。未来独立 CLI 可采用目标接口：

```powershell
persona-speech create --person <person-id> --topic "<主题>" --audience "<听众>" --minutes 20 --web
persona-speech research --session <session-id>
persona-speech draft --session <session-id>
persona-speech render-audio --session <session-id> --voice <voice-id>
```

这些命令目前是产品契约，不是已经实现的程序。

## 未来语音层

语音模型只负责把已审核的 `speech.md` 变成可听内容，不负责偷偷改稿。`delivery.md` 应记录模型、声音 ID、语速、停顿、发音表、生成日期和授权。

- 已故公共人物默认使用明确标注的通用讲述声音，不仿造其真实声纹。
- 在世或私人个人的声音克隆必须有单独、可撤回的明确授权。
- 音频界面持续标识“AI 生成人物视角演讲”，并同步提供文字稿和字幕。
- 重新修改演讲稿后，音频必须标记为过期并重新生成，不能出现稿件与声音内容不一致。

## 可用等级

公开选择器只显示达到 `chat-ready` 或更高等级、`themed_lecture` 为 `true`，且主题落在其高/中覆盖范围的人物。构建者可以显式预览 `draft/private` 人物，但产物页必须显示草稿状态。定题演讲能联网并不代表人物可以讲任何领域；研究补足事实，不能凭空补足人物的思想和教学能力。
