# 圆桌会议项目蓝图

## 一句话定位

让多个已经蒸馏的人物视角围绕同一个问题进行可暂停、可继续、可插话、可回放的模拟讨论；分歧来自各自材料中的注意力、价值和方法，而不是模型为了热闹凭空吵架。

圆桌会议不是历史复原，不声称这些人物真实见过面，也不把生成台词冒充本人原话或当代表态。

## 用户提供什么

- 2--6 位参与人物；第一版固定 3 位。
- 一个可讨论的问题，而不只是宽泛主题。
- 讨论目标，例如澄清概念、比较方案、暴露分歧或形成问题清单。
- 用户角色：旁观、参与或主持。
- 轮次、时间、Token 或费用上限。
- 联网策略：`off / facts_only / research`。
- 是否在结束后生成编辑讨论稿。

## 用户得到什么

1. **实时圆桌：** 人物明确可辨，发言真正回应前文。
2. **交互控制：** 暂停、继续一回合、继续一节、插话、指定回应、结束。
3. **逐轮记录：** 原样保存每次发言和必要的后台元数据。
4. **编辑讨论稿：** 删除重复、重建论证推进，但不篡改立场。
5. **研究附录：** 区分人物材料、现代事实和模型即兴推演。

## 产品原则

### 人物上下文相互隔离

每次人物发言都是一次独立调用，只加载该人物包、圆桌适配层、共享事实简报和必要的会话上下文。不得把所有人物规范混入同一个“演员提示词”，否则不同人物会逐渐收敛成一个通用助手。

### 主持器不拥有观点

主持器负责调度、压缩上下文、发现重复和执行用户控制，不替人物总结“正确答案”，也不把自己变成第四位思想家。

### 共享事实，分别解释

当代议题需要联网时，由事实台形成所有人物共享的中立简报。事实只有一份，人物可以对其意义、权重和行动后果作不同判断。

### 前台自然，后台可审计

用户默认只看到头像、姓名和自然发言。证据 ID、事实 ID、推演类型和主持决策保存在后台；用户要求“查看依据”时再展开。

### 暂停必须真正停止

点击暂停后，不再接受迟到的模型输出写入正式记录。会话状态持久化，恢复时从最后一个已提交回合继续，不重演、不跳步。

## 系统角色

| 角色 | 职责 | 不得做什么 |
| --- | --- | --- |
| 主持器 | 选下一位发言者、指定回应目标、判断停顿和收敛 | 输出自己的立场、代替人物和解 |
| 人物发言器 | 依据单一人物记忆回应具体论点 | 读取其他人物私有记忆、伪造原话或会面 |
| 共享事实台 | 核验会改变判断的当前事实 | 搜索“人物应该怎么想”、为立场背书 |
| 文稿编辑器 | 将已发生的讨论整理成文章 | 新增参与者没说过的实质论点 |
| 渲染层 | 显示头像、姓名、状态和控制按钮 | 要求模型自行输出说话人标签或界面文案 |

## 第一版讨论机制

一场讨论分为若干“节”，每节推进一个窄问题：

```text
开场：每个人提出自己的初步判断
回应：每个人选择一个最重要的真实分歧
深化：澄清概念、给反例、修改立场或指出代价
节末：主持器形成共识、分歧、下一问的后台摘要
```

轮次不是机械的 A-B-C 循环。第一轮保持均衡；之后优先选择被直接质疑、能够补入新方法或尚未回应关键论点的人物。没有新内容时允许人物不发言，不能用改写旧话填充轮次。

## 用户控制

| 操作 | 运行时含义 |
| --- | --- |
| 开始 | 固化配置与人物版本，建立首节问题 |
| 暂停 | 更新状态并取消/废弃在途生成 |
| 继续一回合 | 只提交下一位人物的一次发言 |
| 继续一节 | 运行到节末或触发停止条件 |
| 我想插话 | 会话转为等待用户输入，插话成为共同上下文 |
| 指定回应 | 下一回合优先由指定人物回应指定发言或主张 |
| 结束讨论 | 停止人物生成，转入文稿整理 |

单次会话至少包含 `session.json`、`turns.jsonl`、`transcript.md`、`essay.md` 和 `provenance.md`。若发生联网，再保存 `fact-brief.json`；`state.json` 可由 `session.json` 的运行状态拆出，但两者不得长期互相冲突。

## 实施顺序

### 阶段 0：协议层（本次执行）

- 固定上下文隔离、轮次、主持、联网、暂停恢复和输出规则。
- 建立 JSON Schema、运行提示和人物圆桌适配层。
- 保持人物包 `roundtable=false`，只允许构建者显式预览。

### 阶段 1：Agent 文本原型

- 人物：孔子、庄子、费曼。
- 主题：“人应该怎样学习，才能形成自己的判断？”
- 固定三人、三轮、纯文本，用户可继续或停止。
- 保存真实试验记录，不为通过测试临时改提示。

### 阶段 2：可恢复的最小运行时

- 实现状态机、逐回合提交、取消在途生成和恢复。
- 先提供 CLI，再为 Web/桌面界面复用同一运行核心。

### 阶段 3：编辑稿与依据审计

- 从已提交回合生成讨论稿、分歧图和来源附录。
- 验证编辑器没有新增人物未说过的实质论点。

### 阶段 4：产品界面与语音

- 人物卡座位、流式发言、暂停/继续按钮和回放。
- 语音是渲染层，不改变文本事实、人物版本和会话状态。

## 第一场试验的准入说明

孔子、庄子和费曼目前均为 `draft/private`，且人物清单中的 `capabilities.roundtable=false`。第一场仅允许仓库构建者使用 `preview_override=true` 私有试验，界面持续显示“未通过圆桌评测”。只有完成 [`08-评测与验收.md`](./08-评测与验收.md) 的门槛后，才分别提升人物成熟度和能力开关。
