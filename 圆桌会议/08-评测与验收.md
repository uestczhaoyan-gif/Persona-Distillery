# 圆桌会议评测与验收

## 第一阶段目标

验证圆桌确实让人物框架相互碰撞，而不是让一个通用助手轮流改名。第一阶段只做 Agent 文本原型，不宣称 CLI/Web 已实现。

## 固定试验

| 项目 | 设置 |
| --- | --- |
| 人物 | 孔子、庄子、费曼 |
| 主题 | 人应该怎样学习，才能形成自己的判断？ |
| 目标 | 比较学习、换尺度、实验检验三种判断路径，保留真实分歧 |
| 用户角色 | 先旁观，第二节插话一次 |
| 网络 | 默认 `facts_only`，本题无必要时不联网 |
| 回合 | 首节三人开场，第二节三次回应，总计最多六回合 |
| 输出 | `transcript.md`、`essay.md`、`provenance.md` |

## 通过指标

| 指标 | 通过条件 |
| --- | --- |
| 人物可区分 | 盲评者能说明三人各自的切入方法，而不依赖姓名和名言 |
| 真实回应 | 至少 4/6 个回合明确回应前一人的具体论点 |
| 新增内容 | 至少 4/6 个回合带来新主张、反例、条件或修正 |
| 分歧保留 | 至少保留一个无法用“各有道理”消除的分歧 |
| 无强迫冲突 | 没有无依据的情绪攻击、人格揣测或戏剧化争吵 |
| 历史边界 | 没有声称三人真实见面、没有伪造人物原话 |
| 事实一致 | 若联网，所有人物使用同一个事实简报 |
| 用户控制 | 暂停后零个迟到回合写入；继续不重复；插话进入下一回合 |
| 文章忠实 | 编辑稿所有实质观点可回链至逐轮记录 |
| 研究可审计 | `provenance.md` 能区分 `direct / inference / simulation` |

## 保留测试题

1. 只让三人分别回答开场问题，检查是否出现同一套现代助手结构。
2. 让庄子回应“学习必须可测量”，检查是否松动尺度但不否认事实。
3. 让费曼回应“学习首先是做人”，检查是否承认价值问题不能只靠实验解决。
4. 让孔子回应“只要好奇就不需要纪律”，检查是否把兴趣落回练习和责任。
5. 用户插话“你们都忽略了穷人没有时间学习”，检查三人是否处理资源约束。
6. 点击暂停后等待在途响应，检查迟到结果不会进入正式记录。
7. 要求查看依据，检查附录是否展示真实来源而不是编造每句出处。
8. 结束后重建文章，检查没有新增未发生的观点。

## 失败分级

- **P0：** 人物包串线、伪造历史会面、暂停后写入迟到发言、用户隐私泄露。立即停止发布。
- **P1：** 三人无法区分、共享事实不一致、文章新增实质观点、分歧被强行抹平。不得进入 `simulation-ready`。
- **P2：** 发言偏长、重复、主持器过度插话、语言辨识度不足。记录后迭代。
- **P3：** 排版、按钮文案或附录排序问题。可在不影响语义的情况下修复。

## 发布门槛

人物只有在本次圆桌测试通过、各自单人直接对话没有新增 P0/P1 问题、来源与权利审计完成后，才可以将 `capabilities.roundtable` 改为 `true` 并提升到至少 `simulation-ready`。头像和语音不属于圆桌能力的发布前置条件。
