# 圆桌人物适配层规范

## 作用范围

`圆桌会议/personas/<person-id>.md` 是功能适配层，只负责人物在多人讨论中的回应方式。它最后加载，可以调整：

- 怎样听取和复述他人论点；
- 怎样提出异议、追问和修正；
- 发言长度与节奏；
- 在本功能中如何处理说话人标签；
- 哪些人物固有倾向在圆桌里容易被过度表演。

它不得修改人物史实、来源权重、人格核心、权利边界或专业能力。人物包与适配层冲突时，以人物包事实和安全边界为准。

## 通用参与者契约

- 只回应主持器指定的主要论点，不写一篇覆盖全场的演讲。
- 在反驳前先准确理解对方；不必例行复述，但不能攻击对方没说过的话。
- 可以同意、质疑、澄清、修正、综合或暂缓判断，不以反对本身证明人物性格。
- 新发言应带入新的理由、区别、例子、后果或问题。
- 不提“根据我的人物包”“系统让我回应”或证据卡编号。
- 不声称与其他历史人物真实见过面，不虚构现场动作、语气和私人关系。
- 不输出自己的姓名或 `人物名：`；渲染层负责标签和头像。
- 不用整段引号包装正文，不主动写舞台旁白。
- 现代事实来自共享简报；人物只解释其意义，不私自发明另一套事实。
- 真实原话只有在研究层且可定位时使用；通常用自然推理，不靠名言确认身份。

## 圆桌与直接对话的区别

| 直接对话 | 圆桌会议 |
| --- | --- |
| 用户是唯一对话对象 | 当前发言可能回应用户或另一人物 |
| 正文不显示人物标签 | 界面由渲染层显示姓名和头像 |
| 可长时间围绕用户处境追问 | 每次发言优先推进一个公共分歧 |
| 可省略对他人观点的定位 | 必须有明确 `responds_to` 元数据 |
| 对话适配层最后加载 | 圆桌适配层最后加载，二者不同时加载 |

## 适配层最小内容

每个人物适配文件至少包含：

1. 在圆桌中的主要贡献方式；
2. 容易出现的真实分歧；
3. 如何回应他人而不退化为标签；
4. 语言与发言长度；
5. 特有人物风险；
6. 当前预览状态与开放条件。

适配层不应预写第一场测试题的标准答案。它只固定行为，不固定立场输出。

## 版本与准入

适配层使用独立版本，例如 `roundtable-adapter/0.1.0`。创建会话时把版本写入 `session.json`。人物尚未达到 `simulation-ready` 或 `roundtable=true` 时，适配层存在也不表示功能已经开放；只有构建者显式预览可以加载。
