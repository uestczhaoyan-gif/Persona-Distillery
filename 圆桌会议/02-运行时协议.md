# 圆桌会议运行时协议

协议版本：`roundtable-runtime/0.1.0`

## 1. 创建会话

运行时接收结构化配置，而不是从用户第一句话猜人物：

```json
{
  "session_id": "RT-20260806-001",
  "topic": "人应该怎样学习，才能形成自己的判断？",
  "goal": "比较三种形成判断的方法，并保留不能化解的分歧",
  "participants": ["kongzi", "zhuangzi", "richard-feynman"],
  "user_role": "observer",
  "network_policy": "facts_only"
}
```

创建时固定人物包版本和圆桌适配层版本。会话进行中人物包即使更新，也不改变本场已固定版本；用户可另行创建升级后的新会话。

## 2. 准入

正常准入要求：

```text
manifest.readiness ∈ {simulation-ready, publish-ready}
AND manifest.capabilities.roundtable = true
AND visibility 允许当前用户访问
```

构建者预览可以显式设置 `preview_override=true`，但必须同时满足：

- 人物包属于当前工作区且有访问权限；
- 会话保持私有；
- 界面和输出标明预览状态；
- 不自动修改人物 `manifest.json`；
- 试验结果进入评测记录后再决定是否开放。

任一人物准入失败时整场会话不开始，不能悄悄丢掉该人物或换成同名人物。

## 3. 上下文编译

### 主持器上下文

```text
主持器契约
+ 会话配置与用户控制
+ 参与者 ID、显示名和覆盖主题摘要
+ 已提交回合的结构化摘要
+ 未回应主张、共识、分歧和当前节问题
+ 共享事实简报（如有）
```

主持器不读取人物完整证据卡，避免它替人物作思想判断。

### 单个人物上下文

```text
圆桌参与者通用契约
+ 该人物 manifest 与准入信息
+ 该人物规范、核心锚点和对话样本
+ 该人物长期记忆或按需检索工具
+ 圆桌会议/personas/<person-id>.md
+ 当前节问题
+ 共享事实简报（如有）
+ 需要回应的原始发言
+ 其他必要回合的压缩摘要
+ 用户最新插话（如有）
```

禁止加载其他人物的 `03-persona-spec.md`、证据卡、情境记忆或圆桌适配层。其他人物只通过已提交的可见发言进入上下文。

### 编辑器上下文

编辑器读取完整逐轮记录、事实简报、会话配置和研究附录数据，不重新加载人物规范来“补写”更像人物的话。

## 4. 回合生命周期

```text
主持器选择 speaker 与 responds_to
  -> 编译单人物上下文
  -> 人物生成结构化候选回合
  -> 校验 Schema、准入版本和会话状态版本
  -> 检查重复、伪引、越界和事实请求
  -> 原子提交 turns.jsonl
  -> 更新 session state
  -> 渲染姓名、头像与 text
```

只有“提交”后的回合属于正式记录。流式生成的半句话、暂停后到达的迟到响应和 Schema 不合法的响应均不得进入 `transcript.md`。

## 5. 发言选择

第一节开场默认让每位参与者各发言一次。之后主持器按以下优先级选择：

1. 用户指定的人物与回应对象；
2. 被直接质疑且尚未回应的人物；
3. 能对当前分歧贡献新方法、反例或修正的人物；
4. 当前节发言明显偏少的人物；
5. 若没有新内容，结束本节而不是强行轮转。

主持器必须给出内部 `reason`，但前台不显示。不得因“戏剧性”选择与议题无关的攻击，也不得为了发言均衡压过讨论逻辑。

## 6. 一次有效发言

有效发言至少完成一项：

- 提出可讨论的新主张；
- 准确回应一个已有主张；
- 澄清双方使用不同的概念或标准；
- 给出能改变判断的反例、事实条件或行动后果；
- 明确修正自己先前的判断；
- 提出一个能推进当前分歧的问题。

仅复述人物标签、换句话重复旧观点、称赞所有人或无内容地表示“各有道理”，不得标为新回合。

## 7. 用户事件

- `pause`：立刻改变状态版本，取消或废弃在途生成。
- `continue_turn`：生成并最多提交一个回合。
- `continue_section`：运行到节末、用户事件或停止条件。
- `interject`：保存用户原文，下一次主持决策必须处理它。
- `direct_response`：指定人物和目标回合/主张；目标不存在则拒绝。
- `finish`：不再创建人物回合，进入 `finishing`。

用户插话是用户自己的话，不得被改写成人物发言，也不自动进入人物长期记忆。

## 8. 节末与停止

每节结束时，主持器只在后台更新：

- 当前形成的共识；
- 尚未解决的分歧；
- 已被放弃或修正的主张；
- 下一节最值得推进的一个问题。

满足任一条件时停止：用户结束、达到上限、连续若干回合没有新主张、关键分歧已经清楚且无新材料、所有参与者都请求事实核验、风险规则要求停止。收敛不等于必须达成一致。

## 9. 失败处理

| 失败 | 处理 |
| --- | --- |
| 输出不是合法结构 | 对同一请求最多重试一次；仍失败则暂停 |
| 人物越界或伪造引语 | 不提交，记录失败原因，重新生成一次 |
| 需要事实核验 | 暂停人物回合，事实台更新共享简报后重试 |
| 模型或网络超时 | 保持最后已提交状态，允许重试 |
| 用户在生成中暂停 | 递增状态版本；迟到结果作废 |
| 上下文超限 | 压缩较早回合，但完整原文仍保留在本地记录 |

失败重试不得偷偷换人物、换议题或改写用户输入。

## 10. 可见呈现

模型的 `text` 字段不包含人物姓名、Markdown 标题、头像说明或动作旁白。渲染层统一显示人物名称和头像。主持器只在需要宣布节问题、事实核验、暂停原因或结束时短暂出现，不做逐回合点评。
