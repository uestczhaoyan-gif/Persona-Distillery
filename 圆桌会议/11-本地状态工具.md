# 本地圆桌状态管理工具

这是离线工程原型：支持创建、启动、申请一个回合、校验提交、暂停、恢复、用户插话、结束和已审核文章导入。它不调用模型，不自动主持，不进行事实搜索或语义风险判断，不升级人物能力。需要 Python 3.10+ 与 `requirements.txt` 中的 jsonschema。

## 试跑

```powershell
python 圆桌会议/scripts/roundtable.py create --config 圆桌会议/examples/local-session.json --preview
python 圆桌会议/scripts/roundtable.py start --session RT-20261007-900
python 圆桌会议/scripts/roundtable.py request --session RT-20261007-900 | Set-Content -Encoding utf8 圆桌会议/sessions/RT-20261007-900/ticket.private.json
python 圆桌会议/scripts/roundtable.py status --session RT-20261007-900
```

申请只返回票据，不生成正文。外部 Agent 或人工按 [回合 Schema](schemas/turn.schema.json) 准备 turn.private.json，逐项复制票据中的 session_id、turn_id、speaker_id、sequence、section_index，添加正文、回应目标、证据与审核结果，再提交：

```powershell
python 圆桌会议/scripts/roundtable.py commit --ticket 圆桌会议/sessions/RT-20261007-900/ticket.private.json --turn 圆桌会议/sessions/RT-20261007-900/turn.private.json
python 圆桌会议/scripts/roundtable.py pause --session RT-20261007-900
python 圆桌会议/scripts/roundtable.py resume --session RT-20261007-900
python 圆桌会议/scripts/roundtable.py interject --session RT-20261007-900 --text "我的插话"
python 圆桌会议/scripts/roundtable.py resume --session RT-20261007-900
python 圆桌会议/scripts/roundtable.py finish --session RT-20261007-900
```

插话是明确的本地写入操作，完整内容进入本会话的私有事件文件；下一回合必须在 responds_to 中引用对应 EV-ID。它不写人物包。关闭会话只进入 finishing，不声称编辑讨论稿已完成。

## 提交与停止

人物包版本、适配层版本和有关文件 SHA-256 固定在创建时。启动、恢复、申请和提交核对文件，发生变化须建立新会话。草稿需要配置中的 preview_override 及命令行 `--preview`；原型预览只支持历史公共人物，所有输出持续标明“资料不足的私有预览版本”。普通准入要求公开、simulation-ready/publish-ready 且 roundtable=true。

每个申请持有唯一 request_id 和递增 state_version；同一时刻最多一个在途票据。暂停、插话和结束递增版本并废弃票据；迟到、重复或被改动的票据返回 accepted=false，不写正式记录。结构、身份、长度、主张 ID、回应目标和来源 ID 不合法时拒绝；原型没有自动模型修复，调用方应显式修订或暂停。

达到 max_turns、max_sections、no_new_claim_limit 或 session_ready 时进入 finishing。section_ready 在未达节数上限时暂停，可用 `resume --text "下一节问题"` 开启下一节。risk / needs_user / needs_fact_check 暂停。当前只支持 network_policy=off；可选时间/成本预算尚未实现，配置这些字段时明确拒绝。

accepted=true 只证明工程协议和引用 ID 校验通过。moderation、novelty 和实际论证质量由调用方审核，不能因布尔值为真便宣称没有伪造或不当内容。

## 原子快照与导出

生成文件全部保存在被 Git 忽略的 `圆桌会议/sessions/<session-id>/`。`current.json` 通过一次原子替换指向不可变 snapshots 目录，目录中 session.json 为权威状态，turns.jsonl、events.jsonl、transcript.md、provenance.md 是同一次提交的记录和视图。先写完全部文件再切换指针，读者只看到完整旧版本或完整新版本；校验值发现事后损坏时拒绝恢复。未引用快照属于中断产物，不自动当作提交。

这种组织实现了原有 [暂停恢复协议](06-会话状态与暂停恢复.md) 的一致性目标，避免把多个依次替换的根目录文件误称为整体原子操作。文件锁阻止并发写入；崩溃后先确认无活动进程，再检查对应 `.lock`。

编辑器或人工提供符合 [article Schema](schemas/article.schema.json) 的文章，通过 complete 导入。文章必须保留本工具的模拟说明，所有段落回合引用必须包含在 source_turn_ids 并实际存在，分歧参与者必须属于本会话：

```powershell
python 圆桌会议/scripts/roundtable.py complete --session RT-20261007-900 --article 圆桌会议/sessions/RT-20261007-900/article.private.json
```

完整声明文本为：“这是基于材料构建的人物视角模拟讨论，不是历史记录或真实发言。”完成后快照增加 article.json 与确定性渲染的 essay.md，状态变为 completed。它们只使用调用方提供的文章，不补写人物发言、不反向修改 turns.jsonl。文章语义与人物质量仍须人工审核。
