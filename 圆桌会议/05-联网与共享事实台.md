# 圆桌会议联网与共享事实台

## 目的

圆桌联网只负责把所有参与者放进同一个经过核验的事实世界。它不检索“孔子会怎么想”“庄子会支持谁”，也不把网络评论写入人物长期记忆。

## 默认策略

| 策略 | 行为 |
| --- | --- |
| `off` | 不联网；用户给出的条件作为思想实验前提 |
| `facts_only` | 默认不联网；只有用户要求核验，或事实缺口会改变讨论方向时搜索 |
| `research` | 用户主动进入研究层后，允许查原话、反例、当代事实和争议，并展示来源审计 |

圆桌默认 `facts_only`。与直接对话不同，圆桌一旦触发事实核验，必须为所有人物生成同一份共享 `fact_brief`，不能让每个角色单独搜索。

## 触发条件

可触发共享事实台：

- 用户明确要求“联网核验”“查最新数据”或“给出处”；
- 议题依赖当代数字、法律、制度、技术状态或事件事实，错误事实会改变人物分歧；
- 主持器发现参与者围绕一个可核验事实分裂，并且继续推演会放大错误。

不应触发：

- 只为给模拟讨论增加链接；
- 只为搜索人物评价和二手观点；
- 用户已经给出完整假设，当前任务是思想实验；
- 只因为人物已经去世，便例行搜索所有现代名词。

## 事实台流程

```text
识别事实缺口
  -> 暂停当前人物生成
  -> 形成中立检索问题
  -> 搜索、筛选、去重和记录来源
  -> 生成 fact-brief.json
  -> 将同一 brief 注入所有人物和主持器上下文
  -> 恢复讨论
```

事实台不得替人物作价值判断。每条事实应尽量包含时间、范围、定义、来源和不确定性；相互冲突的来源进入 `disagreements`，不能强行选一个让讨论更顺。

## 事实简报的生命周期

- 简报属于本次会话，可被多轮复用。
- 每条事实必须有 `fact_id`，人物回合通过 `fact_ids` 回链。
- 简报不会写入 `02-evidence.md`、`08-context-memory.md` 或人物索引。
- 只有完成正式增量蒸馏和人工审核，才可能进入人物长期记忆。
- 简报过期、用户更改议题或事实定义发生变化时，状态变为 `expired`，重新生成而不是覆盖旧简报。

## 来源与隐私

- 公开人物的公开资料可以按项目网络策略发送给搜索服务。
- 私密人物、用户上传材料和 `research.local/raw/` 不得自动上传。
- 远程模型启动前，应显示本轮会发送的人物摘要、用户发言和事实简报范围。
- API 密钥、完整私人转录和未授权原文不得写入事实简报或 provenance。

## 人物如何使用事实

人物收到的是“本场核验的当前事实”，不是“人物生前知道的记忆”。它可以说：

- 这个事实会改变哪一个判断；
- 哪些判断仍属于自己的方法迁移；
- 哪些价值冲突不会因为事实明确而自动消失。

自然前台不显示 `fact_id` 和检索过程；用户要求依据时，研究层展开事实和来源。
