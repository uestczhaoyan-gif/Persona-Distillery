# Agent 文本原型使用方法

当前阶段允许 Codex、Claude Code 等工作区 Agent 运行纯文本圆桌。它用于验证人物差异、主持调度和会话产物，不等于独立 CLI 或 Web 已实现。

## 启动方式

在仓库根目录新建 Agent 会话，发送：

```text
请执行 `圆桌会议/09-Agent文本原型使用方法.md` 的运行契约，
读取 `圆桌会议/_template/session.example.json` 作为结构参考。
新建一场构建者私有预览圆桌：

人物：kongzi、zhuangzi、richard-feynman
议题：人应该怎样学习，才能形成自己的判断？
目标：比较三种判断路径，保留真实分歧
用户角色：旁观，但允许插话
联网：facts_only

先创建会话并生成第一个回合。不要一次自动跑完整场。
```

## Agent 运行契约

### 1. 创建与准入

1. 读取 [`01-项目蓝图.md`](./01-项目蓝图.md)、[`02-运行时协议.md`](./02-运行时协议.md) 和 [`06-会话状态与暂停恢复.md`](./06-会话状态与暂停恢复.md)。
2. 为每位人物读取 `manifest.json`；正常准入失败时，只有构建者明确授权 `preview_override=true` 才能继续。
3. 固定人物包与圆桌适配层版本，创建本地 `sessions/<session-id>/session.json`。
4. 不自动修改人物包的 `readiness` 或 `capabilities.roundtable`。

### 2. 每个回合

1. 按 [`prompts/moderator.md`](./prompts/moderator.md) 选择一位发言者和具体回应目标。
2. 只为该发言者加载本人人物包；人物规范、核心锚点、对话样本、档案、证据和情境记忆作为内化记忆。
3. 最后加载 `圆桌会议/personas/<person-id>.md`，不能同时加载直接对话适配层。
4. 其他人物只通过已提交发言进入上下文。
5. 按 [`prompts/participant.md`](./prompts/participant.md) 生成一个结构化候选回合。
6. 校验后追加到 `turns.jsonl` 和 `transcript.md`，再更新会话状态。
7. 前台只显示渲染后的人物姓名与自然正文，不显示内部 JSON、卡号和主持理由。

### 3. 用户可说

| 用户说 | Agent 行为 |
| --- | --- |
| “继续一个回合” | 最多生成并提交一位人物的一次发言 |
| “继续这一节” | 运行到节末或停止条件 |
| “暂停” | 先更新状态，停止后续生成 |
| “我想插话” | 进入 `awaiting_user`，等待用户原文 |
| “让庄子回应费曼刚才那一点” | 校验目标后写入下一主持决策 |
| “结束并生成文稿” | 停止人物回合，生成 article、essay 和 provenance |
| “查看依据” | 展开真实 evidence、source 和 fact 引用 |

### 4. 联网

默认 `facts_only`，没有触发条件时不搜索。本题可以在无联网情况下作为方法讨论运行；人物若提出会改变结论的当前事实请求，暂停回合并按 [`prompts/fact-desk.md`](./prompts/fact-desk.md) 生成一份所有人物共享的简报。

### 5. 写入与隐私

- 圆桌会话默认写入被 Git 忽略的 `圆桌会议/sessions/`。
- 不保存用户未确认的完整私人对话到公开模板。
- 评测用预设插话必须明确标为“项目测试输入”，不能记成用户真实意见。
- 人物包保持只读；只有用户明确要求修订人物时才修改。

## 当前原型限制

- Agent 原型可以逐回合保存和恢复，但无法可靠取消已经发送给外部模型的网络请求；只能用状态版本废弃迟到结果。
- 不同 Agent 可能使用不同模型，人物辨识度需要记录模型和人工盲评。
- 当前没有按钮界面，暂停、继续、插话和结束以自然指令代替。
- 第一场基线保存在 `sessions/RT-20260806-001/`，它是项目试验记录，不是公开人物作品。
