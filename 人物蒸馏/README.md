# 人物蒸馏：开放、可审核的自动构建系统

这个子项目负责把来源各异的资料自动整理成统一人物包。它面向两类开源用户：

- 想研究历史人物、思想家或其他公共人物的人，使用**网络搜索模式**；
- 想整理导师、家人、自己或其他身边人物经验的人，使用**用户上传模式**。

两种模式只在资料进入系统的方式上不同。身份确认后，它们都经过相同的解析、来源登记、证据提炼、情境记忆生成、人物规范合成和评测流程，公共可发布包经审核后写入 `personas/<person-id>/`；受限人物的原料、任务与人物包始终位于外部本地库。各功能按实际接入和验收状态使用，不能把目标流水线当作已全部实现。

## “一键”的准确含义

一键不是跳过判断，而是把重复劳动自动化：用户填写一次向导并点击“开始构建”，系统自动运行所有可安全运行的步骤；遇到必须由人负责的事项时暂停，等待确认后从原状态继续。

```mermaid
flowchart LR
  A[创建任务] --> B{输入模式}
  B -->|网络搜索| C[身份消歧与搜索计划]
  B -->|用户上传| D[授权确认与文件体检]
  C --> E[统一资料记录]
  D --> E
  E --> F[解析、转写、去重、切分]
  F --> G[证据卡、反例与人物草稿]
  G --> H[自动评测]
  H --> I{人工发布审核}
  I -->|退回| F
  I -->|通过| J[生成标准人物包]
```

必须暂停的四个关卡：`身份确认`、`授权/隐私异常`、`严重资料冲突`、`发布审核`。除此之外均可无人值守运行。

## 用户入口

未来 UI 应是一个短向导：

1. 输入人物名称/代号与用途；
2. 选择 `网络搜索` 或 `用户上传`；
3. 确认身份、资料权利和处理位置；
4. 点击“开始构建”；
5. 在审核页查看覆盖度、警告、人物卡和测试对话；
6. 选择“保留为私有草稿”或“发布人物包”。

已有 [本地 TXT/Markdown 准备 CLI](08-本地文本准备工具.md)：`scripts/distill.py init / build / status / approve`，处理到人工证据审核。它不自动生成或发布人物包。完整蒸馏 CLI 的后续目标接口如下（不是当前可运行命令）：

```powershell
persona-distill init --mode web
persona-distill build --config job.json
persona-distill status --job <job-id>
persona-distill review --job <job-id>
persona-distill publish --job <job-id>
```

## 开源项目的底线

- 构建过程与最终人物包都应明确标识“人物视角模拟”，不得冒充本人。
- 默认本地优先；上传资料模式默认禁用联网、外部遥测和远程模型。
- 用户提供文件不等于其中所有人都同意被处理或公开。
- 搜索到网页不等于取得全文再发布或训练的权利。
- 自动生成只到“候选人物包”；公开发布始终需要人类审核并留下构建报告。

本地受限包维护：见[私人包本地备份](11-私人包本地备份.md)，默认预检，显式确认后复制到新的本地目录，不产生公开导出。

[私人包撤回与删除](12-私人包撤回与删除.md)默认只读预检；核对计划哈希并显式确认后逐文件删除，不清理未知目录。

新构建契约见[本地蒸馏任务 v2](13-本地蒸馏任务v2.md)：策略与材料声明、外部库初始化、审核及本地文本快照已实现；完整人物合成仍待 M3，旧入口不接收 v2。

M3 候选记录的内部校验接口见[候选证据与情境契约](14-候选证据与情境契约.md)，目前只校验结构及来源关联，不生成完整人物，也不代替语义审核。
