# 人物规范候选

M3.4a 提供 `persona-spec-candidate.schema.json` 与纯本地 `spec_candidate.normalize_spec`。调用者须先通过 `local_merge.read_merge` 获取当前有效目录，不能直接把存储快照当作已核验输入。

候选包括 profile、attention、judgment、dialogue_style、knowledge_limits、language、anchors、examples、gaps。每项描述关联已有 E/M 稳定编号；模型不能指定人物身份、政策、审核状态或头像。结构通过只代表编号关联正确，不证明归纳准确。

只有 active 且 reviewed 的记录进入 `spec_material`。尚有未解决冲突时暂停合成；已撤回、拒绝记录不传入模型。至少一项有效记录，上限 200 项，超限不自动丢掉材料。风格、判断和锚点允许空列表，材料不足写入 gaps，不凑“鲜明性格”。语言模式沿用时代语体规范，证据不足可为 undetermined。

锚点描述何时注意、怎样尝试、何时误用，是可选择的行为倾向，不规定对话逐步输出。原创示例由程序加 original_simulation_not_quote 标识，不能冒充人物原话、真实聊天或独立评测样本。

输出始终 candidate/local_only，绑定整个目录及输入记录哈希。semantic_review_completed、avatar_ready、persona_generated 均为 false；这不是完整可用人物包。此节点只实现合同与原创合成测试，本机模型生成、人工修订、文档生成、头像和最终包组装后续接入。M2 的真实体验验收仍待模型，当前没有改动默认人物对话行为。


## M3.4b 本地生成

在资料所有者自己的本机交互终端运行（占位路径和哈希需替换为实际外部本地任务）：

```powershell
python 人物蒸馏/scripts/local_spec.py --library D:/PrivatePersona/jobs --job sample-job --merge <合并哈希> --model <已安装本机模型> --confirm-local-storage --confirm-local-service
```

不要通过云 Agent 执行真实私人任务或捕获内容。CLI 仅输出候选哈希、计数与未完成标记。策略先检查，具体 Ollama 模型身份预检后再读合并；只传当前有效记录，不传被拒绝、撤回的历史版本。前后复核来源与模型，无工具、无代理或远程模型。

单次预算：上下文 32768、输出上限 8000、温度 0.2、seed 20261008、HTTP 超时 60 秒，消息总上限 50000 UTF-8 字节。超限整批停止；这些是工程限额，不能代替设备容量测试或语义质量验收。

外部 `specs/<哈希>/` 保存绑定、请求开始记录、规范候选及校验和；未完成标记最后移除，同组合拒绝再次执行或覆盖。失败现场保留，当前不自动重试。隐藏思考和原始模型回复不保存；生成的候选本身可能含私人摘要，仍只能留在外部库。

该入口没有组装 manifest、人物 Markdown 或头像，也不直接改变现有四个人物对话。下一步仍需规范候选的当前性校验、人工修改及包构建，最终验收不得跳过真实试聊与人物特色检查。
