# 人物包迁移工具

当前已实现 M1.3b 只读预检和 M1.3c 显式本地生成。默认仍是 dry-run；只有同时提供 `--apply`、预检哈希和本地存储确认才写入新目录。不调用模型，新运行入口尚待政策检查接入后开放。

## 用法

在本机准备策略 JSON，例如把公开历史人物复制为仅本地的 v2 草稿：

```json
{
  "policy_version": "1.0",
  "subject_kind": "historical_public",
  "sensitive_data": false,
  "material_basis": ["public_source"],
  "review_status": "candidate",
  "execution_policy": {"mode": "local_only", "allowed_services": []},
  "distribution_policy": {"mode": "local_only"}
}
```

以下是命令格式，替换策略与库目录为实际本地路径。依赖 `requirements.txt` 中的 jsonschema：

```powershell
python 人物蒸馏/scripts/migrate_persona.py personas/kongzi --library D:/PersonaPrivateLibrary --policy D:/local-policy.json
```

源包可以是六类人物，但策略人物类型必须与源 manifest 一致，不能通过迁移把熟人改成历史公众人物。第一版只支持 local_only 执行与传播；不会继承公开发布资格。声明敏感、私人或回忆材料的源包也必须处于仓库外；不要把私人数据先导入公开工程再迁移。

默认输出只有是否通过、待复制文件数、生成文件名、排除角色及存储提示。`--show-plan` 显示详细的本地身份/路径、候选 manifest 与文件哈希，**不要把私人包的详细计划粘贴给远程 Agent 或上传**。私人资料的命令在本机执行，不能用云端 Agent 的文件读取来替代本地处理。

## 检查与复制范围

- 目标为 `<library>/<person_id>/`，必须尚不存在；源与目标库不得互相包含。
- 私人库必须与工程分离，不能在任何带 `.git` 的仓库或 worktree 内；忽略目录也不例外。
- 拒绝网络路径、Windows 网络映射盘、父目录穿越、符号链接/junction/reparse point，以及已知或配置的云同步目录。
- 已知目录检测无法发现所有自定义备份/同步软件，后续写入仍需明确确认处理位置；不会宣称绝对隔离。
- 只纳入 manifest 声明的文件及索引声明的 SQLite、向量和 records 依赖，不扫描复制整个目录。
- `raw/`、`research.local/`、隐藏路径、会话目录不能作为复制来源；未声明的文件不纳入。
- 对话日志不复制，计划生成新的空白日志；使用示例暂不复制，避免把完整生成对话无意迁移。源文件保留不变。
- 候选包使用 `manifest.v2.json`，不保留可被旧运行时发现的 `manifest.json` 副本。当前预检并不实际生成它。
- 哈希用于后续检测预检之后的源文件变化；“检查成功”不代表资料真实性、发布授权或人物质量审核通过。

## 显式生成与恢复

先检查 dry-run 的结果、目标存储位置与 `plan_sha256`，再执行同样参数并追加：

```powershell
python 人物蒸馏/scripts/migrate_persona.py personas/kongzi --library D:/PersonaPrivateLibrary --policy D:/local-policy.json --apply --confirm-local-storage --expect-plan-sha256 "从预检结果复制的64位哈希"
```

确认表示用户已核对该目录不会被其他同步/备份服务外发。程序重新检查文件哈希与目录边界，计划变化时拒绝执行；不会改变源包，不写回公共人物索引，不继承旧发布资格。新包含审核材料、空白对话日志、`manifest.v2.json` 与本地 `migration-report.json`。

生成期间使用库级 `.migration.lock`（记录进程 ID 与时间）和包内 `.migration-incomplete.json`。生成不覆盖既有包，未完成标记最后移除；所有 v2 读取器都必须拒绝带此标记的包，不能仅凭 manifest 已出现就加载。

中断后，在确认没有其他迁移进程运行时，以同一源、策略、哈希和确认参数追加 `--resume`。只复用哈希匹配的完整文件；发现新文件、人工修改、源变化、损坏/半写文件或错误标记会停止并保留现场，不擅自删除或覆盖。此类情况须本地核查，或选择新的干净目标库从原始源重新生成。崩溃遗留锁也需核对记录中的进程后处理，不自动解锁他人的工作。

成功生成表示文件复制和版本转换完成，**不表示真人质量评测、发布审核或新运行时已经可用**。

## 开发验证

`tests/test_persona_migration.py` 使用原创虚构文件测试六类人物、只读性、外部库、Git/cloud/network 边界、索引依赖与摘要输出。私人库不能在 Git 内，因此这些测试使用仓库外系统临时目录；其他测试可以继续使用 `.work/tmp`。Windows 沙箱可能需要允许外部临时夹具和本机回环测试，不应为让测试通过而取消生产路径检查。
