# M3 候选证据与情境契约

`candidate_records.normalize_candidates(payload, chunks, policy)` 是本地构建器的内部接口，没有直接读取真实私人资料的云端入口。调用方须在读取正文前验证外部位置和策略；此函数再验证策略、已有片段及候选结构，不调用模型、不写文件、不发布。

模型响应只包含 evidence、memories、gaps 三个数组。证据记录字段为 card_type、claim、evidence_summary、interpretation、limitations、chunk_ids、topics、confidence；情境记录字段为 title、period、situation、observed_move、tension、dialogue_use、chunk_ids、topics、confidence。材料不足时允许空候选并明确 gaps，不凑数量。

程序根据真实存在且校验和匹配的片段生成 source_id、location、证据/记忆编号，模型不能自行设置审核状态、传播政策或来源定位。每条最多 12 个片段，单批最多 40 条证据和 40 条情境，最多 256 个输入片段；字段与总量有上限。metadata_only 不作内容证据，重复记录、未知片段和模型附加字段会拒绝。

输出证据与情境沿用现有 evidence-card/context-memory Schema；另附 lineage 记录每条关联片段的 checksum 与内容指纹。E/M 编号只在本批内确定，后续增量合并必须用指纹维护稳定映射，不能直接覆盖人物已审核编号。JSONL/Markdown 生成属于后续集成。

所有输出保持 candidate/local_only，模型不能提升为 reviewed。输入敏感标记传播到派生策略；仅用户回忆的材料不能直接生成 fact/direct_view，须保留转述或综合性质。混合来源仍需人工分辨，结构校验无法证明概括正确、确有独立来源或回忆属实。

semantic_review_completed=false、persona_generated=false 是明确边界：片段关联证明“引用来自哪里”，不证明“结论被它支持”。尚未执行真实模型提炼、审核采纳、稳定增量合并、完整人物合成或发布；工程测试使用原创虚构资料。


## M3.2 本地提炼入口

准备好 v2 外部任务并完成 `local_distill.py` 的身份、材料及必要敏感审核和 build 后，在资料所有者自己的本机终端运行：

```powershell
python 人物蒸馏/scripts/local_candidates.py --library D:/PrivatePersona/jobs --job sample-job --model <已安装的本机模型> --confirm-local-storage --confirm-local-service
```

示例路径是占位，不是项目工作目录。不要通过云 Agent 调用真实私人任务或捕获终端。CLI 要求交互终端，仅打印计数、候选状态和运行哈希；内部接口供本地应用使用。明确确认的本机服务必须由用户控制，回环地址检查不等于操作系统对该服务实施了网络隔离。

入口先检查策略和外部路径，再核验模型元数据；随后校验审核指纹、输入变更及快照完整性，才允许一次无工具的本机推理。使用具体 Ollama 适配器，不允许云模型、重定向或代理。前后复核模型身份与输入；不完整、截断、工具请求、非法 JSON 和伪造来源均不能成为完成产物。

当前每个输入/模型/提示组合只有一次尝试，没有自动重试或恢复。固定温度 0、seed 20261008、上下文 32768、输出上限 8000；HTTP 超时 60 秒。提示中的材料 JSON 上限 40000 UTF-8 字节，另有片段数量与长度上限；超限整批停止，不悄悄截掉材料。这些是工程限额，不代表任何真实模型的容量或质量已验收。

外部任务下 `candidates/<运行哈希>/` 保存绑定信息、请求开始标记、规范化候选与文件哈希。先写 `.incomplete`，全部成功才移除；失败保留现场，同组合拒绝覆盖或再次推理。不保存原始回复或隐藏思考；候选仍可能含材料摘要，因此全部留在外部本地库。不要手工移除标记绕过状态校验。后续审核/恢复节点将提供正式读取和失败处理流程。

此入口不会修改已有文本快照或任务状态，不生成完整人物规范、头像或公开包。结构通过也不证明来源支持结论；真实推理和语义评审仍待完成。
