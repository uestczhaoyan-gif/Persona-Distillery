# 本地蒸馏任务 v2

状态：M1.6a 已冻结 [job v2 Schema](schemas/distillation-job-v2.schema.json) 与[原创虚构配置样例](examples/v2/local-fictional-upload.json)；M1.6b/c 已提供初始化、状态、审核与本地文本准备命令。旧 `distill.py` 拒绝 v2 和伪装成 v1 的新策略，不能直接把样例交给旧入口。

v2 删除旧 `privacy` 布尔开关组合和按人物类型统一索取 `consent` 的方式，改用完整 `policy` 与针对材料的 `material_declaration`。六类人物均可建立本地候选任务，质量目标与发布权限分开。

`policy` 与人物包使用同一独立契约；subject.kind 必须与 policy.subject_kind 一致。本阶段任务仅接受 upload、local_only 执行与传播、candidate 材料状态，不支持远程服务或直接发布。已从公开来源取得的资料也可作为本地文件导入；自动网络采集不在这个入口中。

材料声明记录声明人、有效日期格式、处理权利确认、是否包含私人通信和第三方审核状态。用户回忆须明确确认其回忆性质；含私人通信时必须给出本机授权记录路径。普通公开材料、原创虚构、自述或非通信回忆不一概要求正式授权文件。Schema 验证声明形状，不替用户证明真实权利。

`third_party_review=pending` 允许先建立任务，但构建器必须等待处理后才能使用材料。配置中的路径由后续本地运行器检查，Schema 通过不表示目录安全、授权文件存在、材料审核完成或人物质量合格。私人配置本身可能含身份与路径，同样不得交给云 Agent。

后续接入顺序：外部非同步任务目录与不可变配置 → 针对材料的审核记录 → 本地文本准备 → M3 候选证据/人物生成。任何报告不得把文本切分记作完整人物蒸馏，也不得把 candidate 自动升级为 reviewed。

## 初始化与状态

把虚构样例复制到自己的仓库外、非同步配置目录，按实际本机情况修改路径。配置文件、输入目录、授权记录与生成任务目录均须在本地私人位置；输入目录、任务库和人物输出目录不能互相包含。授权记录不得混入将要作为材料解析的输入目录。

```powershell
python 人物蒸馏/scripts/local_distill.py --library "D:/PrivateJobs" --confirm-local-storage init --config "D:/PrivateConfig/job.json"
python 人物蒸馏/scripts/local_distill.py --library "D:/PrivateJobs" --confirm-local-storage status --job local-v2-fixture
```

初始化仅冻结 `job.v2.json`、`paths.private.json` 与初始状态，不读取输入正文、不调用模型、不生成正式人物。结果 `identity_review` 表示等待身份及材料审核；`persona_generated=false` 始终如实输出。CLI 不输出私人身份、完整路径和正文。

初始化使用库锁和 `.initializing` 标记，失败现场保留，已有任务不覆盖。检查后可选择新的任务 ID，不能删除标记来冒充完整任务。旧 job v1 与新任务状态不互换。

当前不支持 participant map、OCR 或转写，配置这些功能会拒绝；TXT/Markdown 正文准备已接入，自动人物合成仍属于 M3。私人通信授权记录需为非空本地文件，程序不据此自动认定授权有效。

## 本地审核与文本准备

审核记录放在独立的本地目录，避免被当作输入材料。用 JSON 记录自己的真实判断，例如以下结构；测试示例不是对真实资料的审核：

```json
{"reviewer":"fixture-reviewer","note":"仅检查原创虚构测试资料，不包含真人信息","decision":"approved"}
```

可以一次明确确认身份与材料，也可以分别记录。仅在检查过实际本机资料后运行：

```powershell
python 人物蒸馏/scripts/local_distill.py --library "D:/PrivateJobs" --confirm-local-storage approve --job local-v2-fixture --gate identity material --record "D:/PrivateConfig/review.json"
python 人物蒸馏/scripts/local_distill.py --library "D:/PrivateJobs" --confirm-local-storage build --job local-v2-fixture
```

身份确认前 build 不读取正文；材料审核绑定当前输入及私人通信授权记录的指纹。配置中的第三方待审状态可由这一实际材料审核记录解决，不把配置标签自动改为已审核。检测到联系方式或疑似凭据会进入 `sensitivity_review`，本地核查后可用同一命令形式记录 `--gate sensitivity`。联系方式在片段中遮罩，疑似凭据始终隔离，即使通用审核通过也不进入片段。

build 不联网，只准备 UTF-8 TXT/Markdown。最多 500 文件、单文件 5 MiB、可读批次合计 20 MiB；损坏、空白、其他格式和超限文件记录为隔离，链接目录拒绝遍历。规则筛查不是完整隐私检测，人物归属与材料权利仍须人判断。

成功状态 `review_required` 表示等待证据编写，不代表已生成可聊天人物。快照包含来源 CSV、片段 JSONL、输入清单、策略、材料声明/审核记录、报告与校验索引；user_recollection 等依据在策略和报告中保留，不标成原话。报告明确 `persona_generated=false`、`evidence_cards=0`、`privacy_screening_complete=false`。

同一输入重复 build 复核快照完整性且不新增版本。输入或授权记录变化需要重新材料审核，再用 `build --job ... --update` 创建新快照；旧快照与来源 ID 保留，新增/撤回来源写入报告。被改写的快照拒绝作为已完成结果使用。失败时只有 state 引用的快照生效，未激活目录是中断现场。

任务库本身不是人物包；当前人物包备份/删除命令不会自动处理任务快照、包外输入或审核记录。它们属于撤回时需额外处理的明确范围，不能声称已经一键清除。

快照策略会把实际敏感检测结果合并为 `sensitive_data=true`，不会改写原始冻结声明；遮罩或隔离不自动解除本地限制。
