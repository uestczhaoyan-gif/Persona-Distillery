# 本地蒸馏任务 v2

状态：M1.6a 已冻结 [job v2 Schema](schemas/distillation-job-v2.schema.json) 与[原创虚构配置样例](examples/v2/local-fictional-upload.json)；本节点尚未提供 v2 初始化或构建命令。旧 `distill.py` 拒绝 v2 和伪装成 v1 的新策略，不能直接把样例交给旧入口。

v2 删除旧 `privacy` 布尔开关组合和按人物类型统一索取 `consent` 的方式，改用完整 `policy` 与针对材料的 `material_declaration`。六类人物均可建立本地候选任务，质量目标与发布权限分开。

`policy` 与人物包使用同一独立契约；subject.kind 必须与 policy.subject_kind 一致。本阶段任务仅接受 upload、local_only 执行与传播、candidate 材料状态，不支持远程服务或直接发布。已从公开来源取得的资料也可作为本地文件导入；自动网络采集不在这个入口中。

材料声明记录声明人、有效日期格式、处理权利确认、是否包含私人通信和第三方审核状态。用户回忆须明确确认其回忆性质；含私人通信时必须给出本机授权记录路径。普通公开材料、原创虚构、自述或非通信回忆不一概要求正式授权文件。Schema 验证声明形状，不替用户证明真实权利。

`third_party_review=pending` 允许先建立任务，但构建器必须等待处理后才能使用材料。配置中的路径由后续本地运行器检查，Schema 通过不表示目录安全、授权文件存在、材料审核完成或人物质量合格。私人配置本身可能含身份与路径，同样不得交给云 Agent。

后续接入顺序：外部非同步任务目录与不可变配置 → 针对材料的审核记录 → 本地文本准备 → M3 候选证据/人物生成。任何报告不得把文本切分记作完整人物蒸馏，也不得把 candidate 自动升级为 reviewed。
