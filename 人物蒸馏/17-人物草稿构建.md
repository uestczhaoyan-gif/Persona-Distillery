# 人物草稿构建

## M3.5a 审阅文档

`render_spec.render_views(verified_review, catalog, display_name)` 是纯本地渲染器。调用方必须先经 `read_spec_review` 和 `read_merge` 核验当前规范审核与资料；渲染器再次检查已采纳规范及其证据绑定。拒绝的规范、伪造完成标记或过期目录不能渲染。

输出 11 份 Markdown 视图：档案、人物卡、证据、对话规范、核心锚点、原创示例、评测待办、空会话记录、构建报告、情境记忆和使用样例待办。模型与人工文本作为字面内容处理，转义 HTML、图片与链接语法，避免审阅文档主动加载外部资源。证据编号与出处保留在审阅层；运行时不要求日常回答逐句展示编号。

锚点是可选择倾向，语言与节奏随交流需要调整；材料不足不补写人格套路。原创示例明确不是原话、真实会话或独立测试。文档中的评测与头像继续标为未完成，不把一个 Markdown 文件集合当成完整人物。

此节点不写磁盘、不创建 manifest、不启用人物能力、不发布。后续外部草稿写入器将绑定当前规范审核和资料版本；实际新增完成的人物仍必须具备 AI 头像、真实试聊与相应质量验收。


## M3.5b 外部 v2 草稿

`local_draft.build_draft(library, job_id, spec_review_hash, confirm_local_storage=True)` 只供本地调用。输出到任务冻结的 personas_directory 下 `<构建哈希>/<person-id>/`，不会改写项目 `personas/` 或旧版本。初始 manifest.v2.json 为 draft/private/local_only，所有能力关闭，头像字段不伪造；package_version 暂为 0.0.0，不代表发布版本。

包内包含审阅文档、当前使用的来源台账、有效记录的结构化证据/情境，以及这些记录实际引用的片段。撤回与冲突中的未选版本不会进入草稿。原文片段仍属私人本地资料，不得提交 Git 或外发。build-binding.json 指向原本地任务与规范审核，checksums.json 保存完整文件清单。

写入先建立 `.build-incomplete`，复查材料与审核未变后完成；相同构建只核验复用，损坏和失败现场不覆盖。恢复工具尚待接入。构建结果仍返回 persona_generated=false、avatar_ready=false、quality_verified=false，表示只有待验收草稿，不是新增完成的人物。

v2 Schema 增加可选 files.build_binding。现有本地读取器在显式构建者预览下，会在正文读取前后重新核验绑定、当前来源与全部文件；来源撤回、正文修改、遗漏绑定或未完成构建都会拒绝。普通运行继续要求能力与成熟度，真实预览只能由资料所有者在本机终端执行。

这种构建草稿绑定原任务，不能直接搬家后当作独立人物包使用；本地复制或备份并不取消绑定。后续正式包构建须明确处理迁移、撤回与验收，不手动删绑定规避检查。检查针对普通损坏与过期状态，不是防本地管理员改写整个项目的数字签名系统。
