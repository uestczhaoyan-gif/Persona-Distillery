# 执行与传播策略契约（新规划 M1）

状态：M1.1 已实现旧读取器兼容检查；M1.2 已实现独立策略 Schema；M1.3a 已整合 v2 包 Schema；M1.3b/c 已实现[预检、显式本地生成和恢复](10-人物包迁移工具.md)。M1.4a 已实现中央操作授权逻辑；M1.4b 已实现外部库内部只读接口；M1.4c 已接入实际 Ollama 适配器与只读内部会话，M1.5a 已提供[本机终端预览](../直接对话/docs/私人本地预览.md)，其他私人功能仍未接入。

## 已实现：未知约束不静默忽略

`scripts/package_policy.py` 提供共用兼容检查。直接对话加载、圆桌参与者/证据读取和本地增强摘要导出，在读取人物正文或增强层前检查 manifest：只支持 `schema_version=1.0`；缺失、未知或非字符串版本被拒绝；v1 中混入下表保留策略字段也被拒绝。调用者不能凭 `--preview` 绕过版本检查。

本节点不修改四个人物包、不开放私人预览、不改变证据、不自动迁移。旧 v1 缺失必填 schema_version 的非规范包须补全经核验的版本，不能由程序猜测。已安装的更早软件不能被本次修改追溯修复，因此新版私人包还须使用独立存储和新入口。

## 策略字段（M1.2 已冻结，待整合进 v2 包）

机器契约见 [persona-policy.schema.json](schemas/persona-policy.schema.json)。独立策略对象 `policy_version=1.0` 与人物包版本分别管理。[完整 v2 包 Schema](schemas/persona-package-v2.schema.json) 将策略字段放在 manifest 顶层，`schema_version=2.0`；复用 v1 文件角色和身份字段，测试保证两份 Schema 的策略定义一致。`sensitive_data` 为必填布尔值，表示输入包含敏感材料，不能靠删标签解除实际限制。

v2 暂只支持 private/public 可见性，team 共享留待独立设计。public 必须有 public_approved 策略且质量至少 chat-ready；publish-ready 质量本身不授予公开权限。非 draft 包必须声明 avatar_png/avatar_webp；Schema 只检查路径字段存在，实际文件、尺寸与视觉质量由后续包检查器验证。草稿可以暂缺头像，不能计作完整人物交付。

质量与能力沿用 readiness/capabilities 的语义，不能自动授予外发或发布权限。

| 字段 | 目标值/含义 |
| --- | --- |
| `schema_version` | `2.0`，显式版本升级 |
| `execution_policy.mode` | `local_only` 或 `declared_services` |
| `execution_policy.allowed_services` | 显式允许的服务 ID 清单；local_only 时必须为空 |
| `distribution_policy.mode` | `local_only`、`review_required`、`public_approved` |
| `material_basis` | 非空枚举数组：public_source、self_report、user_recollection、authorized_private、original_fiction；允许混合，不将用户回忆变为本人确认 |
| `review_status` | `candidate` 或 `reviewed`，指人物材料审核；不等同独立质量盲评通过 |

在世公众、在世私人、已故私人包默认且本阶段强制 execution/distribution 均为 local_only。自己或虚构人物若含 authorized_private/user_recollection，同样强制本地；公开可处理来源也不能单凭类型自动变成 public_approved。第三方敏感材料标识将在 job/记录层传播到人物包，不能用纯 public_source 标签掩盖混合材料。

`public_approved` 必须满足 reviewed 及单独 `publication_review`，记录 record_id、reviewer_id、reviewed_on（有效日期）、content_digest（64 位 SHA-256）。Schema 验证记录形状，不验证审核者身份、真实授权或摘要对应的材料；这些由后续发布器核验，当前不支持实际发布。未批准的策略不得携带发布审核记录，避免旧审批被误用。

## 运行检查

检查在读取内容之前进行。输入为人物策略、操作（读取/推理/检索/OCR/转写/生图/导出）、provider 能力、存储位置及输出目标；输出为允许或具体拒绝原因。local_only 模型须核对实际本机 provider，不接受由模型输出声称“本地”。对话用本地模型不代表 OCR、embedding、生图也能自动联网。

同一工作流的有效策略为所有人物和材料限制的交集；任何一个 local_only 使整场生成及衍生文件保持 local_only。缓存与失败日志遵循同样策略。前端隐藏按钮、Prompt 警告和改扩展名都不能替代检查。

### M1.4a 实现边界

`authorize_operation` 验证所有输入策略后计算交集：任一 local_only 禁止服务执行；服务 ID 必须被每个人物允许。读取、推理、检索、OCR、转写、生图均通过同一授权逻辑，本地备份单独禁止服务目标；未知操作和公开导出暂不开放。

`ExecutionTarget` 是可信适配器的内部输入，不是用户或模型的自我声明。`network_enabled=False` 描述处理器不得外联；后续本机模型适配器仍须验证实际端点、模型元数据及调用路径。该函数不是操作系统网络沙箱，也不表示所有工作流已经接入。混合工作流只获得派生限制摘要，不能将摘要代替原始策略重新发布。

### M1.4c 本机处理器边界

`LocalChatSession` 只内部构造 `OllamaProvider`，在正文读取前调用模型元数据检查，每轮重建无代理/无重定向的回环连接并重查云模型标记。调用者必须确认本机服务可信且不转发请求；回环端点不等于对服务进程的外联控制。`network_enabled=False` 表示本项目不允许外部网络处理，适配器仅用本机 IPC/回环传输。受限部署还应由用户在设备侧限制服务外联，不能用模型回答代替本机配置核验。

会话不提供工具、保存、恢复或导出功能，模型不能请求程序上传资料。每轮重新加载并比对包内容哈希，发生编辑要求重新创建会话。当前采用全文字符预算，超限拒绝；实际模型容量及回答质量仍需真实模型验收。

## 存储与迁移合同

- 受限包使用外部私人库和 `manifest.v2.json`，不能留下可供旧解析器加载的 legacy `manifest.json` 副本；旧解析器只扫描旧入口，因此不应发现新版私人库。
- 当前四个人物不批量原地升级。迁移工具先 dry-run，明确来源、目标、策略与影响；验证后在新目录构建，保留原始输入与可回退记录，不删历史证据。
- 私人包回滚保持私人位置和限制，不能通过降级 schema 恢复到公开仓库。需对旧副本作隔离时应列明路径，不能盲目递归删除。
- 仅以 `visibility=private` 放在公共仓库不够；`.gitignore` 也不能保护已跟踪文件。目录、Git 跟踪状态和已知云同步路径都要检查。
- 新入口识别政策版本后再读取文件；未知版本失败关闭。受限正文、摘要、图片和提示词不能进入云 Agent 上下文。
- 开源程序无法阻止用户有意改代码或截屏；工程验收覆盖本项目提供的路径，不承诺绝对防传播。
