# 执行与传播策略契约（新规划 M1）

状态：M1.1 已实现旧读取器兼容检查；本页 v2 字段与迁移为下一节点的实现合同，尚不能用于加载私人包。

## 已实现：未知约束不静默忽略

`scripts/package_policy.py` 提供共用兼容检查。直接对话加载、圆桌参与者/证据读取和本地增强摘要导出，在读取人物正文或增强层前检查 manifest：只支持 `schema_version=1.0`；缺失、未知或非字符串版本被拒绝；v1 中混入下表保留策略字段也被拒绝。调用者不能凭 `--preview` 绕过版本检查。

本节点不修改四个人物包、不开放私人预览、不改变证据、不自动迁移。旧 v1 缺失必填 schema_version 的非规范包须补全经核验的版本，不能由程序猜测。已安装的更早软件不能被本次修改追溯修复，因此新版私人包还须使用独立存储和新入口。

## v2 字段目标

质量与能力沿用 readiness/capabilities 的语义，不能自动授予外发或发布权限。

| 字段 | 目标值/含义 |
| --- | --- |
| `schema_version` | `2.0`，显式版本升级 |
| `execution_policy.mode` | `local_only` 或 `declared_services` |
| `execution_policy.allowed_services` | 显式允许的服务 ID 清单；local_only 时必须为空 |
| `distribution_policy.mode` | `local_only`、`review_required`、`public_approved` |
| `material_basis` | 非空枚举数组：public_source、self_report、user_recollection、authorized_private、original_fiction；允许混合，不将用户回忆变为本人确认 |
| `review_status` | `candidate` 或 `reviewed`，指人物材料审核；不等同独立质量盲评通过 |

在世公众、在世私人、已故私人包默认且本阶段强制 execution/distribution 均为 local_only。自己或虚构人物若含 authorized_private/user_recollection，同样强制本地；公开可处理来源也不能单凭类型自动变成 public_approved。第三方敏感材料标识将在 job/记录层传播到人物包，不能用纯 public_source 标签掩盖混合材料。

`public_approved` 必须满足材料审核及单独发布审核证据；审核记录的结构与身份校验随发布器实现，当前不支持该值的实际发布。仅 schema 验证不能证明真实授权。

## 运行检查

检查在读取内容之前进行。输入为人物策略、操作（读取/推理/检索/OCR/转写/生图/导出）、provider 能力、存储位置及输出目标；输出为允许或具体拒绝原因。local_only 模型须核对实际本机 provider，不接受由模型输出声称“本地”。对话用本地模型不代表 OCR、embedding、生图也能自动联网。

同一工作流的有效策略为所有人物和材料限制的交集；任何一个 local_only 使整场生成及衍生文件保持 local_only。缓存与失败日志遵循同样策略。前端隐藏按钮、Prompt 警告和改扩展名都不能替代检查。

## 存储与迁移合同

- 受限包使用外部私人库和 `manifest.v2.json`，不能留下可供旧解析器加载的 legacy `manifest.json` 副本；旧解析器只扫描旧入口，因此不应发现新版私人库。
- 当前四个人物不批量原地升级。迁移工具先 dry-run，明确来源、目标、策略与影响；验证后在新目录构建，保留原始输入与可回退记录，不删历史证据。
- 私人包回滚保持私人位置和限制，不能通过降级 schema 恢复到公开仓库。需对旧副本作隔离时应列明路径，不能盲目递归删除。
- 仅以 `visibility=private` 放在公共仓库不够；`.gitignore` 也不能保护已跟踪文件。目录、Git 跟踪状态和已知云同步路径都要检查。
- 新入口识别政策版本后再读取文件；未知版本失败关闭。受限正文、摘要、图片和提示词不能进入云 Agent 上下文。
- 开源程序无法阻止用户有意改代码或截屏；工程验收覆盖本项目提供的路径，不承诺绝对防传播。
