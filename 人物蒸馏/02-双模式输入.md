# 双模式输入

用户必须在任务开始时选择一种输入模式。两种模式使用相同的后半段流水线和人物包格式，但权限、风险与默认设置不同。

## 模式 A：网络搜索资料

适合：历史人物、已故公共人物，以及拥有充分公开材料的公共人物。

### 搜索流程

1. 用户给出姓名、年代/地区、领域和构建目的。
2. 系统先返回候选身份及区别，用户确认目标人物。
3. 系统根据主题和时间段生成搜索计划，而不是只搜索“人物名 + 名言”。
4. 按来源等级收集：本人作品与原始影音、机构档案、可靠传记、评论与争议材料。
5. 登记 URL、标题、作者、发布日期、访问日期、许可证/使用状态和内容指纹。
6. 形成覆盖矩阵，主动指出缺少哪些年代、主题或一手材料。

### 搜索计划至少覆盖

- 生平与时间线；
- 核心著作、演讲、访谈或书信；
- 真实决策和行动案例；
- 思想变化与自我修正；
- 可靠的批评、反例和争议；
- 原文与译本的关系；
- 无出处名言和常见误传的排除。

### 网络采集边界

- 遵守站点条款、robots 规则、访问频率、版权与许可证；不绕过登录、付费墙或技术限制。
- 默认保存来源元数据、定位和必要短摘录。只有明确允许时，才把全文打包进可公开人物包。
- 搜索摘要只能作为发现线索，不能替代打开和核验原始页面。
- 搜索结果少、同名歧义大或主要来源仅为转载时，任务应停在“等待补充”，不能凑够数量后自动发布。
- 对在世非公共人物，不得仅凭姓名自动进行大范围人物画像搜索。

## 模式 B：用户上传资料

适合：自己、家人、导师、同事、受访者、已故家族长辈等身边人物，也可用于用户已经合法取得的历史资料。人物已经去世不代表其私人材料和对话中第三方的隐私自动消失，仍要核对资料权利、家属意愿与分享范围。

### 目标支持格式

| 类别 | 格式示例 | 处理方式 |
| --- | --- | --- |
| 文本 | `.txt`、`.md`、`.json`、`.csv` | 编码识别、结构保留、说话人识别 |
| 文档 | `.pdf`、`.docx`、`.html`、`.epub` | 文本提取；扫描件进入 OCR |
| 对话 | 聊天导出、邮件归档、采访稿 | 参与者映射、时间排序、第三方脱敏 |
| 音频 | `.mp3`、`.wav`、`.m4a` | 转写、分离说话人、保留时间戳 |
| 视频 | `.mp4`、`.mov`、字幕文件 | 提取音轨/字幕并保留时间戳 |
| 图片 | `.png`、`.jpg`、`.webp` | 仅在用户选择 OCR 时提取文字 |

具体实现可以分版本逐步支持；不支持的格式应在上传前提示，而不是收下后静默丢弃。

### 上传前确认

- 目标人物是谁，是否在世，是否知道并同意该用途；
- 用户是否有权处理这些文件；
- 是否包含第三方、未成年人、医疗/财务/亲密关系等敏感内容；
- 人物包是仅本地、私有共享还是计划公开；
- 是否允许把文件发送给远程 OCR、转写或大模型服务。

### 默认隐私策略

`local_only: true`、`network_enabled: false`、`remote_processing_allowed: false`、`publish_visibility: private`。用户必须逐项主动修改，系统不得用一个笼统的“同意条款”替代清晰选择。

原始文件放在任务私有区，默认不进入 Git；日志只记录文件 ID、校验值和处理状态，不记录私人正文。多人聊天无法确认授权时进入隔离区，用户可以删除、脱敏或补充授权，但不能直接用于人物合成。

## 为什么不把两种模式混成一个开关

网络模式以来源真实性、身份消歧和版权为首要风险；上传模式以授权、第三方隐私和数据外发为首要风险。界面可以允许用户以后为同一人物创建另一种增量任务，但每个任务必须有唯一模式，构建报告才能明确说明每份资料怎样进入系统。

## 两种模式的共同输出

进入 `normalizing` 阶段后，每份资料都转换为同一来源记录与文本块结构。后续组件不再关心文件来自搜索还是上传，只读取 `source_id`、证据等级、隐私级别、权利状态、定位和规范化正文。
