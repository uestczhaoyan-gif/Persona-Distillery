# 人物包产物契约

任何官方实现、第三方插件或用户脚本，只要声称兼容本项目，都应生成以下结构。输入模式不应改变下游读取方式。

```text
personas/<person-id>/
├─ manifest.json               # 机器读取入口
├─ 00-profile.md
├─ 00-character-card.md
├─ 01-sources.csv
├─ 02-evidence.md
├─ 03-persona-spec.md
├─ 03-core-anchors.md          # 可选但推荐；突出注意力和动作锚点
├─ 03-dialogue-examples.md     # 可选但推荐；原创模拟的行为样本
├─ 04-evaluation.md
├─ 05-dialogue-log.md
├─ 06-build-report.md
├─ 08-context-memory.md        # 可选但推荐；问题、动作、修正与迁移
├─ 09-usage-example.md         # 推荐；提示词、回答、样本性质与简短复盘
├─ assets/
│  ├─ avatar-prompt.md
│  ├─ avatar.png              # 可选，人工审核后加入
│  └─ avatar.webp             # 可选的界面优化版
├─ raw/                       # 本地输入；默认不发布、不入 Git
└─ processed/
   ├─ chunks.jsonl            # 可选；规范化正文/摘要片段，逐行结构化
   ├─ evidence.jsonl          # 可选；证据卡的机器规范版本
   ├─ context-memory.jsonl    # 可选；情境记忆的机器规范版本
   └─ index/                  # 可选；可删除重建的全文/向量索引
```

## 标准文件语义

| 文件 | 必须满足的条件 |
| --- | --- |
| `manifest.json` | 有契约版本、人物 ID、人物包版本、成熟度、可见性、能力开关和入口文件 |
| `00-profile.md` | 有人物 ID、类型、覆盖年代、用途、盲区、授权/风险和版本 |
| `00-character-card.md` | 一页内可读；关键描述可以回到证据；不是系统提示词 |
| `01-sources.csv` | 每份输入一行；具有稳定来源 ID、输入模式、权利、隐私、校验值和定位 |
| `02-evidence.md` | 一卡一主张；区分摘录、解释、反例和可用范围 |
| `03-persona-spec.md` | 定义自然对话行为、知识边界、推演方式、研究层展开规则，以及符合 [`07-时代语言与翻译腔规范.md`](./07-时代语言与翻译腔规范.md) 的语言模式 |
| `03-core-anchors.md` | 提炼 4--7 个有证据的突出注意力和动作，并说明误读与过度使用风险 |
| `03-dialogue-examples.md` | 用原创正反例展示人物的注意力、选择与节奏；不是人物原话或固定答案 |
| `04-evaluation.md` | 有独立保留测试、结果、失败案例和发布门槛 |
| `05-dialogue-log.md` | 初始可为空，发布后用于持续改进 |
| `06-build-report.md` | 记录模式、工具版本、输入统计、警告和人工审核状态 |
| `08-context-memory.md` | 不重复观点卡；记录具体问题、可观察动作、失败/张力、迁移用法与来源 |
| `09-usage-example.md` | 至少展示一组启动方式、用户问题、回答和复盘；必须区分真实试聊与项目原创演示，不得冒充人物原话或证据 |
| `processed/chunks.jsonl` | 保存实际提取文本或权利允许的摘要；每条保留来源、定位、隐私和校验值 |
| `processed/evidence.jsonl` | 自动构建时保存证据卡的机器规范数据；与 `02-evidence.md` 使用相同 ID |
| `processed/context-memory.jsonl` | 保存 `M-` 情境记忆；逐条回链来源并标明人工审核状态 |

详细的层次、JSONL 示例、权利模式和当前人物包实际状态见 [`05-信息存储模型.md`](./05-信息存储模型.md)。最小草稿可以暂时只维护 `02-evidence.md`；要获得稳定的直接对话体验，建议同时维护 `03-core-anchors.md`、`03-dialogue-examples.md` 和 `08-context-memory.md`。自动构建器应生成结构化 JSONL，并将 Markdown 作为人工审核视图。

## 最低可用等级

| 等级 | 含义 | 能否用于功能 |
| --- | --- | --- |
| `draft` | 已解析但证据或授权不足 | 仅私有预览，不进入圆桌/故事发布内容 |
| `chat-ready` | 单人对话基本评测通过 | 可用于直接对话；界面显示早期版本 |
| `simulation-ready` | 决策案例、反例和边界覆盖充分 | 可加入圆桌会议与故事推演 |
| `publish-ready` | 人工审核、权利和完整评测通过 | 可按授权范围分享或公开 |

“有 50 张卡”不能自动等于高等级。来源是否独立、主题是否覆盖、重要主张能否定位、是否存在反例和人物是否有权被公开模拟，共同决定等级。

## 兼容性规则

- `person-id` 一经发布保持稳定；显示名、人物卡和版本可以变化。
- 来源与证据 ID 不因重新排序而变化；删除来源时保留撤回记录并重建受影响索引。
- 下游功能只依赖正式人物包，不能直接读取某个构建器的临时目录。
- 下游功能应先读取 `manifest.json`，再按其中的 `files` 定位 Markdown/CSV；不要把文件名硬编码在多个模块中。
- 新增字段允许旧客户端忽略；删除或改变必填字段语义时升级契约主版本。
- `capabilities.themed_lecture` 是向后兼容的可选能力；字段缺失时必须按 `false` 处理。它只表示人物包允许被定题演讲加载，主题仍须落在覆盖范围内。
- `files.usage_example` 对旧人物包保持可选；新建或升级的人物包应提供 `09-usage-example.md`，但运行时不得把它当作历史证据或要求模型复读其中答案。
- 私密人物包的导出文件应携带可见性和处理限制，不能因复制目录而自动变成公开人物。
- `research.local/` 不是正式发布包的一部分；远程 Agent 只能读取按 [`06-受保护材料处理规范.md`](./06-受保护材料处理规范.md) 过滤导出的摘要。

## 发布包与本地工作区

本地工作区可以包含原始文件、缓存、OCR 中间图、模型响应和失败日志；发布包只包含授权允许的文件。公开发布前，应生成一份文件清单并验证其中没有密钥、绝对本地路径、聊天附件、未脱敏正文或可恢复的已删除内容。
